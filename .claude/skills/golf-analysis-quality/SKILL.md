# 골프 분석 품질 판정 — 회귀 검증

## 언제 이 스킬을 쓰는가

분석 코어(`golf_swing_analyzer/analyzer/` 패키지) 수정 전후 비교, 또는 실제 영상을 넣었을 때
결과물이 이상해 보인다는 보고를 받았을 때. 코드 구현이 아니라 **결과물 판단**이 목적.

## 회귀 검증 자산

| 파일 | 용도 |
|---|---|
| `golf_swing_analyzer/video/일반.mp4` | 일반인 스윙 — 임팩트 wy가 어드레스 wy보다 낮을 것으로 예상되는 기본 케이스 |
| `golf_swing_analyzer/video/프로.mp4` | 프로 스윙 — 카메라 각도에 따라 임팩트 wy < 어드레스 wy일 수 있는 케이스 (argmax 방식이 필요했던 이유) |
| `golf_swing_analyzer/video/프로2.mp4` | 프로 스윙 2번째 샘플 — 23MB 장편이라 adaptive 샘플링(200프레임 상한) 경로까지 함께 검증됨 |
| `golf_swing_analyzer/reference_db.json` | 프로/아마추어 기준 통계 누적 DB — **현재 비어있음("{}")**. 지표별 샘플 n≥2 있어야 `compute_score()`가 동적 임계값을 쓰고, 그 전엔 하드코딩 기본값(analyzer/scoring.py L.79-85) 사용 |

(2026-07-04: mp4 3종 + img.png가 `golf_swing_analyzer/` 루트에서 `golf_swing_analyzer/video/`로 이동됨. `reference_db.json`은 루트에 그대로 있음 — analyzer 패키지 분리 시 경로 계산을 한 단계 위로 보정해뒀으므로 영향 없음)

이 3개 영상 + DB 상태를 기준선으로 삼는다. 새 영상으로 "좋아졌다"를 주장하려면
반드시 이 기존 영상들에 대한 결과와 비교해서 회귀가 없는지 먼저 확인한다.

**검증 이력**: golf-platform 1단계(analyzer/ 모듈 분리) 직후 2026-07-04에 테스트 영상 3종
(일반.mp4·프로2.mp4·프로.mp4) 전체 회귀 통과 확인(7단계 전부 감지, frame_data/annotated_frames/
trajectory_pts 인덱스 정합 유지). 다음 코어 변경 시 이 3종 전부 다시 확인할 것.

## 판정 절차

### 1. 페이즈 경계 정합성 확인
UI Tab2의 "손목 Y 궤적 진단" 차트(app_v2.py L.556 부근)가 이미 이 용도로 만들어져 있다 —
새로 만들지 말고 이 차트/표를 활용한다.

체크할 것:
- [ ] "백스윙" 구간: 시작 Y > 끝 Y (손목이 위로 올라감 = 픽셀 Y 감소) — 반대면 오탐
- [ ] "임팩트" 구간 끝 Y ≈ "어드레스" 시작 Y (다운스윙 후 손목이 어드레스 높이 근처로 복귀) — 크게 벗어나면 카메라 각도 이슈이거나 감지 실패
- [ ] 7단계가 모두 감지됐는가 (`phases_detected` 길이, 5개 미만이면 UI에서 경고 표시됨 — app_v2.py L.441-443)
- [ ] 각 페이즈의 프레임 수(`count`)가 0에 가깝게 쏠려있지 않은가 (특정 구간이 통째로 씹혔을 가능성)

### 2. 수치 상식 검증 (하드코딩 기본값 기준, ref_db 비어있는 현재 상태)
| 지표 | 기본 임계값 | 근거 |
|---|---|---|
| 척추각 변화량(어드레스~임팩트) | warn>7°, crit>12° | analyzer/scoring.py L.92 |
| X-Factor(어깨-골반 꼬임) | 20°~80° 범위 밖이면 경고 | L.110 |
| 어드레스 무릎 굴곡 | 165° 초과(너무 펴짐)면 경고 | L.129 |
| 백스윙 톱 왼팔 각도 | 140° 미만(너무 굽음)이면 경고 | L.143 |
| 어깨 최대 회전 | 60° 미만이면 경고 | L.155 |

수치가 이 범위를 벗어난 게 "스윙이 실제로 문제"인지 "감지 자체가 틀렸는지" 구분한다 —
1번(페이즈 경계 정합성)이 깨져 있으면 수치 이상은 감지 오류가 원인일 가능성이 높다.

### 3. 변경 전 결과 vs 변경 후 결과 절대 혼동 금지
코드 변경 전후 같은 영상을 다시 돌린 결과를 비교할 때, "이전 실행 결과"와
"방금 실행 결과"를 표로 명확히 분리해서 제시한다. 섞어서 "개선됐다"고 단정하지 않는다.

```
| 지표 | 변경 전 | 변경 후 | 차이 |
|---|---|---|---|
| 척추각 변화량 | ... | ... | ... |
| X-Factor | ... | ... | ... |
| 감지된 페이즈 수 | ... | ... | ... |
```

### 4. 성급한 결론 금지
- 영상 1개만 돌려보고 "고쳐졌다" 단정 금지 — 최소 테스트 영상 3종 모두 확인
- 특정 영상에서만 좋아지고 다른 영상에서 나빠졌으면 "회귀 발생" — 즉시 보고, golf-code-change로 원인 조사 위임
- reference_db.json이 비어있는 상태에서 나온 점수는 "하드코딩 기본값 기준"이라는 점을 항상 명시

## 출력 형식

```
[검증 대상] 어떤 변경/영상
[페이즈 경계 정합성] 통과 / 이상 발견 (구체적으로)
[수치 상식 검증] 표
[변경 전후 비교] 표 (해당 시)
[결론] 회귀 없음 / 회귀 발생 — 성급한 "개선됨" 단정 없이
[다음 액션] 문제 발견 시 golf-code-change로 위임 문구
```

## golf-code-change와 경계

- 결과물을 **판정**하는 요청 → 이 스킬
- 판정 결과 문제가 확인돼 코드를 **고치는** 작업 → `golf-code-change` (체크리스트 A1~A9 통과 필수)
- 이 스킬은 코드를 직접 수정하지 않는다
