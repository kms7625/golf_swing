# 골프 프로젝트 세션 회고 — 대화 지식 영속화

## 목적

이 프로젝트는 작업마다 즉시 커밋·푸시하므로(2026-07-05 이후 정착 —
프로젝트 메모리 `workflow-commit-and-autonomy` 참조) 대부분의 지식은 이미
기록돼 있다. 회고의 역할은 **"빠진 것만 줍는 것"** — 대화 중 확정됐지만
커밋·CLAUDE.md·`.claude/skills/golf-*`·메모리 어디에도 안 남은 지식을 찾아
영속화한다. 같은 내용을 재기록하면 문서만 부푼다. **기록 전에 반드시 당일
git log와 CLAUDE.md, 8개 golf-* 스킬 파일, 메모리 인덱스(MEMORY.md)를
확인**해서 이미 있는 것은 건너뛴다.

## 수집 대상 (이 5종만 — 대화를 훑으며 추출)

1. **확정된 아키텍처/구조 결정과 이유** — 예: "코어 보존 + 껍데기 교체" 방향 확정 (2026-07-04)
2. **코드에서 발견된 사실·불변식** — 실제로 파일을 읽고 확인한 알고리즘 동작 원리,
   CLAUDE.md와 실제 코드의 불일치(예: 세션 상태 키 이름 차이, 줄번호 오차)
3. **설계 결정과 채택 이유** — 왜 이 방식을 골랐고 어떤 대안을 버렸는지
   (예: 실시간 감지 방향 A/B 중 선택 이유)
4. **새로 발견된 알려진 한계·함정 패턴** — 재발 시 오판을 막을 지식
   (예: 사이드바 안내 임계값과 실제 판정 임계값의 불일치)
5. **워크플로우 변경** — 스킬 신설·개정, 회귀 검증 절차 변경 등

수집 대상이 아닌 것: 일회성 조회 결과, 코드 diff 자체(git이 이미 보관),
진행 중이라 결론 안 난 논의.

## 저장소 라우팅 (지식 유형 → 목적지)

| 지식 유형 | 목적지 |
|---|---|
| 코드·알고리즘 불변식, 코드 자체에서 확인된 사실 | CLAUDE.md 해당 섹션 |
| 체크리스트 항목·판정 기준·경계 정의 | 해당 `golf-*` SKILL.md 파일 (`.claude/skills/`) |
| 진행 상태·아키텍처 결정·사용자 선호 | 메모리 (`~/.claude/projects/.../memory/` — MEMORY.md 인덱스 동기화 필수) |
| 재사용 프롬프트 | 프로젝트 루트 파일 (예: `골프코칭_스킬세트_생성_프롬프트.md` 전례) |

잘못 넣으면 낡거나 못 찾는다. 특히:
- **수치 하드코딩 금지** — 빠르게 낡는 수치(reference_db.json 샘플 수 등)는 값 대신 조회 방법을 기록
- 스킬 신설·개정이 생기면 이 스킬 파일의 표, golf-prompt-engineer의 "스킬 지도",
  다른 golf-* 스킬의 "경계" 섹션도 함께 갱신해 라우팅이 어긋나지 않게 한다
- CLAUDE.md와 실제 코드가 어긋난 걸 발견하면(예: 이번 세션에서 발견한 섹션 줄번호 오차, 세션 상태 키 이름 차이) 대화로만 남기지 말고 CLAUDE.md를 갱신하거나 최소한 golf-code-change/golf-ui-ux 스킬에 "실제 코드 기준 확인 필요" 경고로 남긴다

## 절차

1. 당일 git log(`git log --oneline --since=midnight`)와 CLAUDE.md, 8개 `golf-*` SKILL.md,
   메모리 인덱스(MEMORY.md)를 훑어 "이미 기록된 것" 목록을 만든다
2. 대화를 시간순으로 훑으며 수집 대상 5종을 추출하고, 1의 목록과 대조해 미기록 항목만 남긴다
3. 항목별로 라우팅 표에 따라 기록하고 **항목별 개별 커밋·푸시** (한국어 메시지)
4. 미기록 항목이 없으면 "회고 결과: 전부 기록돼 있음"으로 종결 — 억지로 기록거리를 만들지 않는다

## 출력 형식

```
[회고 범위] 세션 주제 1줄
[이미 기록됨] 대조 결과 n건 (나열은 간단히)
[미기록 발견] n건 — 항목·유형·목적지
[기록 완료] 반영한 파일 나열 (또는 "기록할 것 없음")
```
