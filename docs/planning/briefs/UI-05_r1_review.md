## 4. 실제 기능과 제안의 경계

- 현행은 기기에서 각도를 계산하고 촬영 종료 후 `/score-live`에 손목 Y와 각도 데이터를 전송한다. 녹화본의 정식 분석은 별도 영상 업로드다. 이 동작과 문구를 대조했다.
- 한글 HUD는 기존 SPINE/SHOULDER/HIP의 표시 이름 후보이며 계산 변경이 아니다. 어깨선·골반선은 영상 평면의 기울기이고, UI-04 최대각·변화량과 같은 값으로 설명하지 않았다.
- 준비 체크·인식 배지·녹화 표시·원인별 복구·재촬영·미인식 시 이전 수치 비우기·이탈 선택은 UI 제안이다. 자동 준비 검증이나 새 기능 구현을 완료했다고 기록하지 않았다.
- KEY_JOINTS는 어깨·골반·무릎만 확인하므로 전신·발끝·클럽 포함을 자동 확인한다고 주장하지 않는다. 현행 녹화 지원은 별도이며 capturing 상태 자체가 녹화 성공을 보증하지 않는다.
- 짧은 촬영 판정은 유효 프레임 20개 미만이다. 초 단위 최소 촬영 시간이나 촬영 거리·정확도 수치를 새로 만들지 않았다.
- **NOT_RUN**: 앱·카메라·모델·녹화·서버 분석·브라우저·모바일·키보드·보조기술·빌드·코드 테스트. 정적 시안 작업이며 코드 변경은 없다.

## 5. 상태·보존 검증

STATE **18→19**에서 APR-11(UI_STRUCTURE, target_revision=1) 추가, **19→20**에서 ASSET-13(GENERATED, ui_revision=1, structure_revision=1) 추가. approval_id와 approval_sha256_or_null은 null이다. 최신 안내는 맨 위에 덧붙이고 기존 역사 문장을 보존한다.

검증 결과: **파일·상태 무결성 PASS**. STATE JSON 파싱 성공, revision=20, 기존 승인 **10개**와 자산 **12개** 객체가 그대로 유지됐다. state_revision·approvals·asset_records 외 모든 JSON 값 동일, 기존 Markdown 역사 문장 보존. 새 승인 APR-11은 UI_STRUCTURE 하나뿐이며 UI_IMAGE 승인은 추가하지 않았다. ASSET-13은 GENERATED·승인 필드 null이고 PNG SHA-256과 일치한다. 승인 시각 참조 4개의 SHA-256도 각각 APR-06·07·08·10과 일치한다. 저장한 생성 입력과 실제 호출 입력 동일, 브리프·대조 기록 로컬 링크 누락 0개, 끝 공백 오류 0개.
