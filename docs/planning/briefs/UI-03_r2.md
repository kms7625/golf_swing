## 2. 화면 목적·배치·규격

목적은 처리 대상·진행률·현재 단계·뒤로 갔을 때의 결과를 확인하는 것이다. 첫 행동은 기다리기, 보조 행동은 뒤로 가기다. 비회원·KO·밝은 테마·데스크톱 **16:9 한 장**, 생성 목표 **1920×1080px**. 아래 치수·색은 제안값이며 승인 CSS 수치가 아니다.

- 공통 상단 아래 약 1160px 폭의 중앙 작업 영역. 제목 → 파일 → 코발트 진행률 면 → 5행 목록 → 이탈 안내 순서.
- 제목은 남색 굵은 고딕, 파일명은 작은 파일 아이콘과 함께 표시.
- 코발트 면의 왼쪽은 분석 진행률, 오른쪽은 약 110px의 굵은 흰 30%. 그 아래 전체 폭 막대와 단계 기준 설명. 막대 채움은 **30%**.
- 현재 행은 옅은 파랑 면·왼쪽 선·화살표·진행 중 배지로 강조. 완료 체크·대기 빈 원과 배지도 유지.
- 하단 구분선 아래 왼쪽 뒤로 가기, 오른쪽 결과 안내 세 문장. 버튼은 보조 행동으로 남겨두고 다시 분석 시작 버튼은 추가하지 않는다.
- 제안색: #FFFFFF / #152040 / #2448D8 / #ECF1FF. UI-02 r3의 코발트 면과 큰 숫자를 이어가되 UI-03의 정보 순서는 유지한다.
- 실제 PNG 치수·막대 비율·글자·배치 차이는 생성 후 대조한다. 생성 파일의 크롭·리사이즈·코드 글자 덧그리기는 하지 않는다.

## 5. 동작·검증 경계

- ISSUE-02의 뒤로 가기 → UI-02 파일 선택, 조회 중지·활성 요청 무효화·늦은 성공/오류 응답 배제는 r1 개선안 그대로다. 화면 이탈이 서버 분석 취소를 뜻하지 않는다. App.tsx의 현행 동작을 구현 완료로 보고하지 않는다.

- 실제 코드·API·브라우저·보조기술 검증은 NOT_RUN. 이번 확인은 PNG 디코딩·치수·해시·원본 보존과 문구/배치 육안 대조다. 코드 변경·빌드·커밋 없음.
