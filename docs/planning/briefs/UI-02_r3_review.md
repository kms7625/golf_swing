## 3. 실제 신호·데이터 한계

`auto_detect_swing_window`는 빠른 스캔에서 **양손 손목 평균 Y**를 얻고 평활화한 뒤, 톱 후보→이후 최댓값의 **진폭 최대 후보**를 선택한다. 따라서 손목 높이 파형과 설명의 신호명은 코드와 맞는다. 화면 Y는 아래로 증가하므로 파형은 손목이 높을수록 위로 보이는 방향을 사용한다. API가 실제 속도나 오디오 파형을 제공한다고 주장하지 않는다.

중요한 기존 예시 정정: **8초 이하 영상은 스캔 없이 전체를 반환**한다. r2의 8초·1.2–4.8초 합성값을 그대로 ‘파형 기반 자동 감지’로 보여주면 현행 코드와 모순된다. r3는 **12초 중 3–9초, 현재 6초** 합성 예시로 바꿨고 `예시 데이터`를 표시했다. 실제 `일반.mp4`를 분석한 결과는 아니다.

현재 `/auto-window` 응답과 `AutoWindowResponse`에는 시작·끝만 있다. 결과 화면의 `Waveform`은 인덱스와 단계 경계를 쓰므로 업로드 전체 영상의 시간축 데이터와 동일하지 않다. 후속 구현에는 감지 스캔의 원본 타임스탬프·손목 Y 및 성공/전체반환 사유 계약이 필요하다. 이번에는 코어·서버·타입·컴포넌트를 수정하지 않았다.

실패 때 파형·음영 처리, 8초 이하 전체 반환의 별도 상태, 두 핸들 접근 이름·키보드 조작은 [브리프](UI-02_r3.md)에 기록했다. 데이터 미확보 시 허구의 파형이나 자동 감지 음영을 표시하지 않는 제안이다.
