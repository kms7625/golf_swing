## 유지·변경 계약

흰 페이지·배치·고딕 서체 느낌·굵은 숫자·문구·구조·버튼 크기를 보존한다. 코발트·남색 UI의 역할을 짙은 초록과 라임으로 교체한다. 각 화면은 **정확한 16:9, 2048×1152 목표의 독립 데스크톱 한 장**이며 콜라주를 만들지 않는다. 실제 출력 치수·배치 편차는 [대조 기록](accent-lime_review.md)에 공개한다.

| 화면 | 변경 | 보존 |
|---|---|---|
| UI-01 r3 | 업로드 버튼 라임 채움·짙은 글자/아이콘/초점선, 기록 띠 옅은 녹색, 오른쪽 실사형 골퍼를 같은 포즈·패널의 실루엣/일러스트로 전환 | 비대칭 2열·큰 2줄 제목·버튼 두 개·기록 띠·이미지 예시 표기·전문 |
| UI-02 r4 | 요약 면·CTA 라임 채움, 큰 6.0s 짙은 초록, 파형/핸들/선 짙은 초록, 감지 범위 라임 계열 음영, 오기 → **자동 감지 구간** | 세로 영상·체크·통합 타임라인 한 개·3/6/9/12초 합성값·개인정보 전문·실루엣 |
| UI-03 r3 | 진행 패널 옅은 녹색·큰 30% 짙은 초록, 라임 막대·완료 원 채움, 짙은 상태 아이콘, 뒤로 가기 별도 초점선 | 중앙 배치·5단계 순서·완료/현재/대기 기호·30% 합성 상태·이탈 안내 3문장 |

UI-03 뒤로 가기는 흰 버튼/짙은 경계 → 흰 간격(목표 5px) → 짙은 외부 초점선 순서로 명확히 구분한다. 라임 채움과 흰 페이지 사이에 조작 경계를 알아야 하는 버튼·핸들에는 짙은 선을 둔다. 완료 ✓, 현재 ▶, 대기 ○ 및 상태 문구를 함께 유지한다.

## 색 토큰

라임 글자·얇은 선·아이콘을 흰 면에 놓지 않는다. 흰 글자를 라임 위에 놓지 않는다. 색 토큰은 생성 지시값이며 PNG 픽셀의 정확한 일치를 보장하지 않는다.

## 대비 계산

일반 본문 목표는 4.5:1 이상이다([W3C SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)). 필수 조작 경계·상태 그래픽은 인접색 대비 3:1을 확인한다([W3C SC 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)).

각 8비트 sRGB 채널을 255로 나눈 c에 대해 c≤0.04045이면 c/12.92, 그 외 ((c+0.055)/1.055)^2.4로 선형화한다. L=0.2126R+0.7152G+0.0722B. 대비=(밝은 L+0.05)/(어두운 L+0.05). Python으로 계산했고 아래 표는 소수 셋째 자리로 표시했다. 합격 여부는 반올림 전 값으로 판단했다.

| 전경 / 배경 | 대비 | 용도·판정 |
|---|---:|---|
| ink / white | 16.141:1 | 제목·숫자·본문 충족 |
| body / white | 8.096:1 | 본문·보조 설명 충족 |
| accent-line / white | 6.804:1 | 링크·기호·경계·초점 충족 |
| ink / lime | 12.518:1 | CTA·요약 숫자·배지 글자 충족 |
| body / lime | 6.279:1 | 라임 면 본문 충족 |
| accent-line / lime | 5.277:1 | 라임 위 글자·선 충족 |
| ink / soft-fill | 14.574:1 | 진행 숫자·현재 행 충족 |
| body / soft-fill | 7.310:1 | 진행 설명·기록 안내 충족 |
| accent-line / soft-fill | 6.144:1 | 파형·감지 라벨·선 충족 |
| lime / progress-track | 5.277:1 | 진행 채움/트랙 구별 충족 |
| progress-track / soft-fill | 6.144:1 | 트랙/패널 경계 충족 |
| lime / white | **1.289:1** | 글자·필수 단독 경계로 금지 |

라임 음영은 범위 라벨·짙은 핸들·테두리와 함께 사용하며 음영만으로 상태를 전달하지 않는다. 이 표는 설계 토큰 검증이다. 생성 PNG는 대표 픽셀을 별도 검사하며 실제 앱의 CSS·키보드·보조기술 적합성 판정과 구별한다.

## 문구·데이터 계약

원본 브리프의 문구를 유지한다: [UI-01](UI-01_r2_brief.md), [UI-02](UI-02_r3.md), [UI-03 r2](UI-03_r2.md), [색 참고 r1](UI-03_r1.md).

UI-02 3–9초, 선택 6.0s, 현재 6.0s, 전체 12초와 UI-03 30%는 합성 예시이다. 실제 감지/분석 결과를 새로 만들지 않는다. UI-03 이탈 안내는 기존 제안이며 서버 취소 기능을 뜻하지 않는다.

## 생성·등록·검증

내장 image_gen 편집을 화면별로 한 번씩 요청한다. 각 호출 참조 순서는 **해당 원본 편집 대상 → UI-03 r1 색 느낌**이며 모두 먼저 열람했다. 필요시 같은 도구로 국소 교정하고 시도·차이를 남긴다. 코드 크롭·리사이즈·텍스트 덧그리기는 하지 않는다.
[실제 입력 전체](accent-lime.imagegen.txt)에 호출별 프롬프트와 참조를 보존한다. 도구 자동 캐시 원본을 지정 PNG로 바이트 그대로 복사한다. 직접 쓰는 산출물은 docs/planning/에 한정한다.

- [UI-01 r3](../mockups/UI-01_r3.png) → ASSET-09 / ui_revision 3
- [UI-02 r4](../mockups/UI-02_r4.png) → ASSET-10 / ui_revision 4
- [UI-03 r3](../mockups/UI-03_r3.png) → ASSET-11 / ui_revision 3

STATE JSON은 state_revision **13→14**와 asset_records 끝의 세 항목 추가만 변경한다. 새 항목은 GENERATED, SHA-256 기록, approval_id와 approval_sha256_or_null은 null. 기존 APR-01~07·ASSET-01~08·DEC-02·text_corrections를 포함한 나머지 JSON은 그대로 보존한다. 최신 안내만 상단에 추가한다. 기존 PNG·브리프·기록 보존을 시작 해시와 대조한다.

golf-ui-ux B1~B6은 실행 UI/API/코드를 수정하지 않아 구현 점검 대상이 아니다. 새 i18n 등록·분석 임계값·샘플 재생성·브라우저 테스트는 수행하지 않는다. 파일 무결성·PNG 치수·육안 문구/배치·대표색·대비를 검사하고 결과를 보고한 뒤 **3장 승인 / 수정 요청** 질문 하나로 멈춘다.
