# UI-01 첫 화면 — 첫 시안 생성 브리프

작성일: 2026-10-08 · project_id: `swinglab-web-ux-20261008` · scope_id: `D04-10_D05-07_UI-01` · state_revision: 2 · UI revision: **1** · 구조 revision: **2** · **DRAFT**

D05 4절의 일곱 필드 순서다. 이번 생성 대상은 **UI-01 비회원·KO·어두운 테마 첫 화면 한 장**이다. 구조 동의 근거는 DEC-01 / APR-01이며 시안 승인은 없다. `r1`은 첫 이미지 revision이며, 선택을 반영한 구조 revision 2와 구별한다.

## 1. 화면 목적 / 첫 행동 / 지원 기기와 화면 비율

- 목적: 방문자가 자기 골프 영상을 선택해 분석을 시작하도록 안내한다.
- 첫 행동: **내 영상 바로 업로드**. 실제 표시 문구는 `hero_cta_upload`의 **영상 업로드** 그대로 사용한다. 샘플 체험은 보조 버튼이다.
- 구조 동작 계약: 주 버튼은 접근 가능한 이름이 있는 실제 `<button type="button">`으로 구현할 대상이며 Enter/Space로 파일 선택을 시작한다. 선택한 파일을 UI-02 구간 선택으로 전달하고 취소하면 첫 화면을 유지한다. 현재 코드는 UI-02로 이동한 다음 클릭 div에서 파일을 선택한다. 이 차이는 후속 구현 과제이며 이번에는 코드·동작을 변경하거나 검증하지 않는다.
- 지원 기기: 데스크톱 웹 첫 화면 시안. 모바일은 기존 구조 문서의 제안값 360px 재배치 계약을 유지하되 이미지를 추가 생성하지 않는다.
- 지시서 원문: **데스크톱 16:9(1440×900 기준)**. 1440×900은 계산상 16:10이므로 두 조건은 동시에 충족할 수 없다. 1440×900은 배치 참고 기준으로 보존하고, 명시된 **16:9를 우선하여 1440×810을 생성 목표**로 삼는다. 도구 실제 출력 치수는 생성 후 별도 측정한다. 수동 리사이즈·크롭으로 맞추지 않는다. 이 해석은 사용자 승인된 규격이 아니다.

## 2. 상단·주 영역·보조 영역·하단의 구체 배치

아래 픽셀은 모두 **미승인 제안값**이며 생성 이미지의 실측값이 아니다.

| 영역 | 배치·정보 순서 |
|---|---|
| 상단 | 전체 폭, 약 76px 높이. 왼쪽 `SWING.LAB`, 오른쪽 실시간 캠 → 내 기록 → 테마 아이콘 → KO/EN → 로그인. 업로드와 경쟁하는 큰 상단 CTA를 추가하지 않는다. |
| 주 영역 | 중앙 최대 약 1200px, 좌우 여백 약 120px. 왼쪽 약 650px 폭에 eyebrow → 2줄 제목 → 본문 → 주/보조 버튼. 오른쪽 캐릭터 패널과 약 100px 간격. 버튼과 본문은 왼쪽 정렬. |
| 주 버튼 | 라임 채움·어두운 글자·업로드 아이콘, 최소 약 48px 높이의 독립 버튼. 키보드 초점 상태를 한 번만 표현: 민트 외곽선과 배경 간격으로 라임 면과 구별한다. 버튼 이름은 `영상 업로드`. |

| 보조 영역 | 오른쪽 **9:16 패널** 약 324×576px. 기존 골퍼의 전신·클럽·스윙 궤적·관절 표시가 잘리지 않게 contain 배치. 상단에 기존 KO 키 `샘플 데이터`를 작은 예시 배지로 사용. 하단에 별도의 HTML 계측 문구 자리 세 개를 둔다. |
| 하단 | 같은 첫 화면 하단의 얇은 기록 안내 영역. `내 스윙 기록`, 비회원 안내, 작은 `로그인` 버튼. 실사용 기록·점수·계정 삭제를 만들지 않는다. |

## 3. 정확한 제목·라벨·버튼·대표 데이터

KO 사전은 [i18n.tsx](../../../web/src/lib/i18n.tsx)의 실제 값을 그대로 사용한다. 원문에 없는 문구로 축약하거나 새 카피로 교체하지 않는다. 줄바꿈은 허용하되 글자·문장부호는 보존한다. 브랜드·언어 코드와 영문 계측 수치는 현재 컴포넌트의 리터럴이다.

계측 수치는 현재 Hero의 **고정 예시**이며 실제 분석 결과가 아니다. 생성 시안은 래스터 이미지이므로 HTML 요소를 증명하지 못한다. 구현 시 캐릭터 파일과 계측 텍스트를 분리하고 위 세 문구는 HTML로 렌더해야 한다.

## 4. 컴포넌트 형태·정보 밀도·색/글자 역할

- Club Lime 역할 유지: 짙은 녹색 배경, 밝은 본문/제목, 라임은 주 행동·브랜드, 민트는 계측·키보드 초점, 회녹색은 보조 설명. 참고 CSS의 `#111610`, `#1b2319`, `#f3f7ed`, `#c5f26b`, `#73dacc`, `#b0baaa`는 현행 값이며 이번 시안에는 **미승인 제안값**으로 사용한다.
- 글자: Pretendard 계열의 읽기 쉬운 한국어 sans-serif와 JetBrains Mono 계열의 계측 글자. 폰트 파일은 전달하지 않는다. 생성 이미지의 실제 폰트·정확한 색·대비 적합성은 미확인이다.
- 밀도: 소개·업로드 행동이 왼쪽 첫 시선을 받고, 오른쪽 캐릭터는 기능 이해를 돕는다. 배경 장식, 추가 수치 카드, 강한 빛 효과, 새로운 기능 설명은 넣지 않는다.
- 약 12px 모서리의 버튼과 약 20px 패널 모서리, 여유 있는 간격을 제안한다. 실측 완료값으로 기록하지 않는다.

## 6. 이번 이미지에 넣지 않을 기능·자산

UI-02–08의 별도 화면, 전 화면 콜라주, 모바일 시안, 로그인 모달, 드롭존/구간 슬라이더, 분석 진행, 결과 점수·차트, 사용자 실기록, 관리자·결제·학습 DB·CSV 내보내기, 신규 인물·로고·캐릭터를 넣지 않는다. 하단 기록 안내는 UI-01의 비회원 영역만 표현한다. 오류·로딩·성공의 추가 시안을 만들지 않는다.

빈 기록·샘플 읽기 로딩/오류·권한 상태와 제안값 360px 재배치는 [UI_STRUCTURE.md](../UI_STRUCTURE.md)에서 후속 계약으로 유지한다. 초점의 시각 표현 이외 실제 키보드·파일 선택·반응형·네트워크 동작은 미확인이다.
