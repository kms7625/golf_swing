## 1. 목적과 대표 상태

사용자가 분석 결과의 점수, 지표, 진단과 근거 장면을 첫 화면에서 확인한다. **비회원의 새 분석 직후·미저장·7단계 모두 감지** 상태를 대표한다. 파일명 `일반.mp4`와 모든 숫자는 시안용 합성 예시이며 실제 파일 분석 결과가 아니다. 제품의 샘플 진입 상태(`isSample=true`)와 혼동하지 않도록 `샘플 데이터` 배지 대신 시안 데이터임을 밝히는 `예시 데이터`를 표시한다.

데스크톱 KO 밝은 화면 **16:9 한 장**, 목표 **2048×1152px**, 스크롤 전 뷰포트만 생성한다. 코드로 크롭·리사이즈·글자 합성하지 않고 실제 생성 치수와 차이는 대조 기록에 공개한다. 모바일·다른 결과 상태·스크롤 아래 영역은 별도 이미지로 생성하지 않는다.

## 2. 첫 화면의 배치

| 순서 / 영역 | 배치·역할·정확한 표시 |
|---|---|
| 공통 상단 | 흰 바탕. 왼쪽 `Swing.Lab`, 오른쪽 `실시간 캠` → `내 기록` → 해 아이콘+`테마` → `KO / EN`(KO 밑줄) → 외곽선 `로그인`. 승인 3장의 메뉴·서체 역할을 유지한다. |
| 제목·출처 | `7단계 스윙 분석`; 아래 파일 아이콘+`일반.mp4`, `새 분석 · 미저장`, 작은 `예시 데이터` 배지. 상단에 공유·저장 버튼을 중복 배치하지 않고 지시대로 아래 상세 기능 뒤에 둔다. |
| 총점·등급 | 왼쪽 약 25% 폭의 코발트 면: `TOTAL SCORE`, 가장 큰 흰 숫자 `73`, `등급 B`. 오른쪽 약 75%에는 핵심 지표 네 개를 한 줄로 배치한다. |
| 핵심 지표 4개 | `척추각 변화` **8.2° ⚠**, `X-FACTOR` **17.0° ✕**, `어깨 최대 회전` **72.0°**, `감지 페이즈` **7 / 7 ✓**. 각 이름 옆 작은 `?` 도움말 아이콘과 아래 짧은 설명. 값·단위·기호는 한 묶음으로 줄바꿈을 막는다. |
| 지표 짧은 설명 | 순서대로 `상체 기울기 변화` / `어깨·골반 최대각 차` / `영상 속 어깨선 최대각` / `찾아낸 스윙 단계 수`. 기존 이름·숫자·단위·판정을 대체하지 않는 보조 설명이다. |
| 진단 목록 | `항목별 진단` 아래 §3의 5개 메시지를 서버 순서대로 모두 표시. 얕은 가로 구분선, 경고 행은 ⚠와 `warning`, 양호 행은 ✓와 `good`를 함께 표시한다. 긴 문장은 줄을 나눌 수 있으나 내용을 줄이지 않는다. |
| 대표 장면 | `7단계 대표 장면`과 작은 `이미지 예시`. **어드레스 → 백스윙 → 백스윙 톱 → 다운스윙 → 임팩트 → 팔로우스루 → 피니시** 순서로 같은 크기 썸네일 7개를 한 줄에 배치한다. 얼굴·옷 세부가 없는 남색 전신 골퍼 실루엣, 옅은 파랑 배경. 각 썸네일에도 `이미지 예시` 표시. |

레이아웃 목표: 좌우 여백 약 80px, 헤더 높이 약 90px, 제목/출처 y≈125–230, 점수·지표 y≈265–470, 진단 y≈505–805, 장면 제목·썸네일 y≈850–1110. 좌표는 생성용 제안이며 CSS 규격 승인이 아니다. 첫 뷰포트는 장면 캡션까지 보여야 한다. 화면 아래에 상세 영역의 축소판이나 목차를 그리지 않는다.

| 진단용 추가 값 | 어드레스 무릎 좌 158.0° / 우 160.0°, 백스윙 톱 왼팔 155.0°. 기본 무릎 165°·왼팔 140° 경계에서 모두 good. |

이미지에 넣을 진단 전문(현재 메시지 템플릿의 값만 합성):

1. `척추각 변화량 8.2° — 약간의 상체 흔들림. 7° 이내 유지를 목표로 하세요.`
2. `X-Factor 17.0° — 어깨-골반 꼬임 부족. 백스윙 시 어깨를 더 회전하세요.`
3. `어드레스 무릎 굴곡 적절 (좌 158.0° / 우 160.0°) ✓`
4. `백스윙 톱 왼팔 직선성 양호 (155.0°) ✓`
5. `어깨 회전 충분 (72.0°) ✓`

새 제목 `7단계 대표 장면`, 출처·예시 표시, 지표 설명, 도움말, 아래 표의 개선 문구는 **신규 문구 후보**다. 기존 KO/EN 사전에 등록하거나 코드에 하드코딩하지 않는다. i18n에 이미 있는 `항목별 진단` 제목은 현행 ResultScreen에서 실제로 렌더링하지 않지만 이번 시안에는 표시한다.

## 4. NE-15 용어 설명 / 상태 기호

| 지표 | 도움말을 열었을 때의 설명 후보(이미지에는 열린 팝업을 그리지 않음) |
|---|---|
| 척추각 변화 | 어드레스부터 임팩트까지 상체 기울기의 최댓값과 최솟값 차이입니다. 해당 구간이 없으면 전체 구간 값을 사용합니다. 단위는 도(°)입니다. |
| X-FACTOR | 영상에서 계산한 어깨선 최대각에서 골반선 최대각을 뺀 값입니다. 두 최댓값은 서로 다른 순간일 수 있습니다. 카드의 상태와 항목별 진단은 서로 다른 기준을 사용합니다. |
| 어깨 최대 회전 | 영상에서 어깨선이 수평선과 이루는 각도의 최댓값입니다. 현재 카드에는 상태 판정 기호가 없습니다. |
| 감지 페이즈 | 7개 스윙 단계 중 찾아낸 단계 수입니다. 단계 수가 많다는 뜻이며 각 장면이 정확히 검출되었다는 보증은 아닙니다. |

보조 설명은 현행 계산의 뜻을 알리기 위한 것이며 측정·채점 변경이 아니다. X-Factor의 3D 몸통 회전 측정이나 백스윙 톱 한 시점의 각도라는 설명을 새로 붙이지 않는다. **P5의 ‘참고값’ 전환·감점 제외는 적용하지 않는다.**

기존 `statusIcon`의 ✓/⚠/✕를 유지한다. 이번 한 상태에는 척추 ⚠·X-Factor ✕·단계 ✓가 함께 보인다. 코발트는 총점·주 행동, 짙은 호박색은 경고, 짙은 적색은 crit에 한정한다. 모든 상태는 기호와 글자로도 구별한다. 도움말은 후속 구현 시 지표별 접근 이름·키보드 열기/닫기·초점 복귀를 정의할 대상이다. 정적 이미지가 이 동작의 검증은 아니다.

## 6. 부분 결과 / 결정 필요 / 시각 언어

**ISSUE-12**: 후속 부분 결과 화면에서는 7개 장면 자리를 유지하고, 단계 미검출이면 `단계를 찾지 못했어요`, 검출됐으나 이미지가 없으면 `대표 장면이 없습니다`로 구분한다. 감지 수는 summary 기준, 장면 수는 rep_frames 기준으로 분리한다. 누락 장면을 생성 실루엣으로 실제 결과처럼 채우지 않는다. 이번 대표 상태는 모든 단계·장면이 있으므로 누락 안내는 이미지에 넣지 않는다. 대표 프레임 선택(임팩트 첫 프레임·다운스윙 85%·나머지 중간)은 변경하지 않는다.

**결정 필요 — X-Factor P5**: [연구 제안 P5](../../research/04_swinglab_implications.md)의 감점 제외 또는 참고값 표시는 사용자 미결정이다. 브리프의 미결정 항목으로만 남기며 이번 이미지·점수·진단에 반영하지 않는다. 현행 카드 상태와 채점 진단의 기준 차이도 임의로 통일하지 않는다. 이는 코드·제품 현황을 대조한 기록이며 연구 문헌의 재검증 작업은 아니다.

승인 시각 언어: 흰 배경 #FFFFFF, 남색 고딕 #152040, 코발트 #2448D8, 옅은 파랑 #ECF1FF. 큰 코발트 점수 면, 굵은 흰 점수, 읽기 쉬운 남색 문구, 단정한 작은 모서리, 얕은 구분선. 장면 외 장식 일러스트·게이지·레이더 차트·계측 HUD·라임 변경판 스타일은 추가하지 않는다. 색은 생성용 제안이며 실제 픽셀·대비·폰트 일치는 검증되지 않았다.

## 7. 생성·보존·종료

내장 image_gen으로 신규 시안 한 장을 생성한다. 기존 PNG 세 장은 실제 열람해 시각을 대조하고, **신규 이미지 호출에는 파일 참조 인자를 넣지 않고 [생성 입력](UI-04_r1.imagegen.txt)에 시각 특징·정확한 문구를 명시**한다. 특정 인물·실제 프레임을 사용하지 않으며 실루엣은 합성 예시다. [최종 PNG](../mockups/UI-04_r1.png)를 저장하고 [대조 기록](UI-04_r1_review.md)에 실제 결과·문구·배치·SHA-256을 기록한다.

STATE는 revision 15→16에 APR-09 추가, 16→17에 ASSET-12 GENERATED 추가. 기존 객체·자산·승인·문장은 보존하며 최신 검토 안내를 맨 위에 추가해 오래된 screens/pending 필드와 구별한다. ASSET-12의 approval_id와 approval_sha256_or_null은 null이다. 직접 작성·복사하는 파일은 docs/planning/ 아래 브리프·생성 입력·PNG·대조 기록·STATE 5개다. 생성 도구가 자체 관리하는 캐시 원본은 작업 파일 쓰기와 구별해 기록한다.

실제 앱·브라우저·모바일·키보드·보조기술·빌드·코드 테스트는 **NOT_RUN**. 코드 수정·커밋·다른 화면 생성·UI_IMAGE 승인 추가 없이 결과를 보고하고 **“UI-04 r1 시안을 승인하시겠어요, 수정 요청하시겠어요?”** 한 질문으로 중지한다.
