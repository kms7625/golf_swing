## 1. 화면 목적 / 첫 행동 / 지원 기기와 화면 비율

비회원이 파일과 제안 구간을 확인하고, 영상 아래 두 핸들로 범위를 조절한 뒤 **이 구간으로 분석 시작**을 누른다. KO·밝은 테마·자동 감지 완료 직후, 아직 수동으로 변경하지 않은 대표 상태 하나다. REQ-01·07·08·09 및 ISSUE-01·03·06·11의 기존 개선 의도를 유지한다.

데스크톱 **16:9 한 장**, 생성 목표 **1920×1080px**. 영상 내부 목표 **216×384px(9:16)**. 좌표·색은 배치 제안값이며 승인 CSS 치수가 아니다. 출력 치수·내부 비율은 생성 후 대조한다. 생성 원본을 코드로 크롭·리사이즈하거나 텍스트를 덧그리지 않는다.

후속 동작 제안: 파형의 자동 제안 음영은 최초 감지 범위로 유지하고, 수동 편집 범위는 필름스트립 테두리·핸들로만 갱신한다. 이번 이미지는 두 범위가 같은 초기 상태다. 현재 재생선은 별개이며 재생 중 범위 핸들을 이동시키지 않는다. 필름스트립 클릭은 탐색, 핸들 드래그는 구간 변경으로 역할을 구분한다.

접근성 구현 계약: 두 핸들 각각 이름 **`분석 구간 시작`**, **`분석 구간 끝`**, 현재 값은 초 단위를 포함해 읽는다. Tab으로 각 핸들에 진입하고 화살표로 0.1초 조절, Home/End는 해당 핸들의 허용 범위 내 이동, 초점 외곽선을 표시한다. 별도의 현재 재생 위치 조작 이름은 `현재 재생 위치`. 핸들 최소 간격 0.5초, 감지 중 또는 선택 길이 1초 미만 CTA 비활성화는 현행 계약을 유지한다. 파형은 접근 가능한 요약 설명을 제공한다. 이는 정적 이미지로 검증할 수 없는 후속 요구다.

`분석 구간 시작` / `분석 구간 끝` / `현재 재생 위치`는 비가시 접근 이름 후보다. 새 후보는 후속 구현 시 KO/EN 사전에 등록할 대상이며 이번에는 코드를 수정하지 않는다. 기존 메뉴·개인정보·CTA는 최신 [i18n](../../../web/src/lib/i18n.tsx) 원문을 따른다.

### 실제 감지 신호 확인

- [pipeline.py auto_detect_swing_window](../../../golf_swing_analyzer/analyzer/pipeline.py): 8초 이하에서는 스캔 없이 전체를 반환한다(L77–80). 긴 영상은 320×180 프레임의 양손 손목 평균 Y=`(lms[15].y + lms[16].y) / 2 * 180`와 원본 시간 `fi / fps`를 수집한다(L84–101).
- 약 0.5초 창으로 평활화하고, 손목 Y의 로컬 최솟값 후보 이후 4초 창 최댓값까지의 진폭을 비교한다. 유효 후보 중 **진폭이 가장 큰 한 사이클**을 고른다. 시작은 앞쪽 어드레스 높이 기준, 끝은 임팩트 뒤 약 2초에 기본 padding 1초를 더하는 방식이다(L108–178). 속도·소리·클럽 추적·7단계 분류 기반 감지가 아니다.
- 따라서 `손목 높이 변화`는 실제 신호와 맞는다. 파형은 화면 Y가 작을수록 손목이 높다는 점을 반영해 **위로 갈수록 손목이 높은 방향**으로 표시한다. 절대 신체 높이·미터 단위·관절각으로 해석하지 않는다. 문장의 ‘움직임이 큰’은 진폭 기반 선택의 짧은 설명이며 경계 산정·여유 구간 전체를 설명하는 문장은 아니다.
- [Waveform.tsx](../../../web/src/components/Waveform.tsx)는 결과의 `wristY`를 인덱스 `i`에 매핑하고 reversed YAxis와 phaseBoundaries 음영을 그린다. 같은 계열의 손목 Y 신호지만 **결과의 프레임 인덱스 파형을 업로드 원본 시간축에 그대로 재사용하면 안 된다**. 이번에는 단계별 음영도 가져오지 않는다.
- [현재 /auto-window](../../../server/main.py)는 `start_sec`, `end_sec`만 반환하며 [AutoWindowResponse](../../../web/src/lib/types.ts)도 같다. **UI-02에서 파형을 이미 받을 수 있는 상태가 아니다.** 후속 구현에는 감지 스캔의 원본 타임스탬프·손목 Y·성공/전체반환 사유를 전달하는 별도 계약 검토가 필요하다. 후보 없음·포즈 부족·8초 이하의 전체 반환은 현재 예외 실패와 구분되지 않는다. 이번 시안에 임의 성공 근거를 실제 데이터처럼 연결하지 않는다.

### 이미지에 넣지 않는 상태 계약

감지 실패 시 **자동 감지 음영과 성공 설명을 제거하고, 확보된 유효 손목 표본이 있으면 중립 회색 파형만 표시하며 없으면 `손목 움직임을 표시할 수 없어요`(신규 후보)로 대체; 필름스트립과 전체 영상 범위의 수동 핸들은 유지**한다.

실패 안내는 현행 `trim_detect_failed`: `자동 감지에 실패해 전체 영상이 선택됐어요. 슬라이더로 스윙 구간을 직접 정해 주세요`. 감지 중은 현행 `스윙 구간 자동 감지 중...`과 CTA 비활성화. 짧은 영상 전체 반환은 실패로 단정하거나 ‘큰 움직임을 찾았다’고 설명하지 않고, 후속 구현 시 별도 전체 선택 상태로 다룰 대상이다. 실패·감지 중·짧은 영상 화면은 이번에 생성하지 않는다.

## 4. 컴포넌트 형태·정보 밀도·색/글자 역할

승인 r2a의 흰 바탕·남색 고딕·코발트 주 행동·옅은 파랑을 유지한다. 제안색 #FFFFFF / #152040 / #2448D8 / #ECF1FF. 길이 숫자는 요약 카드의 가장 큰 요소, 완료 상태는 그보다 작게, 안내는 본문 크기로 위계를 둔다. 큰 코발트 면과 두꺼운 숫자로 r2보다 강조하되 추가 장식·어두운 카드·네온·계측 HUD를 넣지 않는다. 버튼은 단정한 둥근 사각형. 파형은 굵은 코발트 선, 선택 핸들은 손잡이 무늬, 현재 위치는 남색 선과 삼각형으로 색 외 모양도 구별한다.

## 6. 이번 이미지에 넣지 않을 기능·자산

단계 미리보기, 7단계명·단계 카드·결과 음영, 점수·관절각·코칭, 감지 실패 화면, 다른 화면·모바일·빈 업로드 영역·콜라주는 제외한다. 필름스트립 장면을 분석 단계 결과처럼 표시하지 않는다. 새 API나 실제 파형 기능을 구현하지 않는다. 파일 교체 취소 시 기존 초안 유지, 새 파일 확정 시 구간·감지 초기화라는 r2 동작 제안은 유지한다.

실제 브라우저·기기·키보드·보조기술·번역 전환·분석·삭제 정책 검증은 **NOT_RUN**. 코드 변경·빌드·테스트 실행·커밋은 범위 밖이다.

## 7. 구조·자산·종료 계약

구조 revision 2를 기반으로 이번 명시 수정 요청의 통합 타임라인 배치를 제안한다. 과거 APR-03·APR-04·APR-06을 r3 이미지 승인으로 확대하지 않는다. STATE JSON은 **state_revision 9→10**과 **ASSET-07 추가**만 변경하며 기존 기록 객체는 보존한다. 새 자산은 UI-02 / ui_revision 3 / GENERATED / approval_id null / approval_sha256_or_null null.

브리프를 먼저 저장하고 [생성 입력](UI-02_r3.imagegen.txt)으로 내장 도구를 실행한다. [시안](../mockups/UI-02_r3.png) 확보 후 [대조 기록](UI-02_r3_review.md)에 실제 치수·SHA-256·문구·배치 차이와 검증 범위를 기록한다. 보고 마지막에 **승인 / 수정 요청** 질문 하나를 남기고 중지한다.
