# UI-02 업로드·구간 선택 — 첫 시안 생성 브리프

작성일: 2026-10-08 · project_id: `swinglab-web-ux-20261008` · scope_id: `D04-10_D05-07_UI-02` · state_revision: **4** · UI revision: **1** · 구조 revision: **2** · **DRAFT**

D05 4절의 일곱 필드 순서다. 대표 상태는 **파일 선택 후 자동 구간 감지가 완료되어 수동 조정할 수 있는 상태**, 비회원·KO·어두운 테마 한 장이다. APR-03은 구조 동의와 생성 요청이며 UI_IMAGE 승인이 아니다. 역할 적용은 `ROLE_GUIDED`; 독립 하위 에이전트 실행 없음.

## 1. 화면 목적 / 첫 행동 / 지원 기기와 화면 비율

- 목적: 선택한 영상과 시작·끝·선택 길이를 확인하고 분석 구간을 확정한다. 관련 REQ-01·07·08·09.
- 첫 행동: 왼쪽 세로 영상과 오른쪽 구간을 확인·조정한 뒤 **이 구간으로 분석 시작**을 누른다. 다른 파일이 필요하면 **파일 변경**을 사용한다.
- 지원 기기/비율: 데스크톱 웹 **16:9**, 생성 목표 **1536×864px**. 영상 자체는 **9:16**, 제안 크기 **288×512px**. 외부 카드와 영상 사각형을 구별한다. 수치는 모두 미승인 제안값이며 도구 출력 치수는 생성 뒤 실측한다. 출력은 임의 크롭·리사이즈하지 않는다.
- 빈 드롭존 상태는 **다음 revision 후보**로만 기록하고 이번에는 생성하지 않는다. 감지 중·실패·모바일도 문서 계약만 남긴다.

| 보조/하단 | 주 버튼 바로 아래 방패 아이콘·개인정보 안내 전문·밑줄 친 `개인정보처리방침`. 한 화면 안에 모두 보이며 별도 기록 띠나 다른 화면을 붙이지 않는다. |

### 구조 개선과 동작 연결 — 모두 후속 구현 제안

| 이슈 | 이번 가시 표현과 구현 계약 | 경계 |
|---|---|---|
| ISSUE-03 | 선택 전 `파일 선택`, 선택 후 `파일 변경`을 이름 있는 실제 버튼과 파일 input에 연결한다. Enter/Space로 열고 Tab 초점을 볼 수 있어야 한다. 이번 이미지는 선택 후 버튼만 표현한다. | 현재 dropzone은 클릭 div·숨겨진 input. 이미지로 키보드 동작을 검증할 수 없다. |
| ISSUE-01 | 파일명을 먼저 보여주고 `파일 변경` 제공. 선택 취소 시 기존 파일·구간 유지, 새 파일 확정 시 이전 구간과 상태를 초기화한다. | 파일 변경 affordance 제안만 반영. 방침 왕복·분석 실패 초안 보존은 기존 구조 문서의 후속 과제이며 이번에 해결 처리하지 않는다. |
| ISSUE-06 | 감지 중/완료/실패 문구를 구별하고 실패 때 수동 조정을 안내한다. 이번 이미지는 완료 상태 하나만 표시한다. | 감지 재시도 버튼·새 API·미확인 처리 시간/용량 한도는 추가하지 않는다. |
| ISSUE-11 | `시작`/`끝`을 각 range input의 실제 label/id로 연결하고 값·단위를 함께 읽게 한다. 상태 영역은 변경 알림에 연결할 대상이다. | 실제 연결·보조기술·초점·대비 검증은 미확인. |

분석 버튼은 현재 코드처럼 감지 중 또는 선택 길이 1초 미만이면 비활성화되는 계약을 유지한다. 현재 slider step=0.1초, 핸들 간 최소 간격=0.5초와 분석 활성화 기준=1초는 서로 다르다. 이번 예시 3.6초는 유효한 활성 상태다. 이 값들은 기존 동작 사실이며 신규 기능이나 승인된 디자인 치수가 아니다.

## 4. 컴포넌트 형태·정보 밀도·색/글자 역할

- **시각 기준은 APR-02가 승인한 UI-01_r1.png**: 짙은 녹색 배경, 밝은 제목·본문, 라임 주 행동·브랜드·선택 상태, 민트 수치·초점·상태, 회녹색 보조 문구, 가는 테두리와 둥근 패널/버튼.
- 현재 CSS에서 읽은 `#111610`, `#1b2319`, `#f3f7ed`, `#c5f26b`, `#73dacc`, `#b0baaa`, 패널 20px·버튼 12px는 생성 참고용 **제안값**이다. UI-01 이미지 승인만으로 토큰의 정확한 수치까지 승인되었다고 보지 않는다.
- 한국어는 Pretendard 느낌의 선명한 sans-serif, 시간은 JetBrains Mono 느낌의 등폭 글자. 실제 폰트 식별·대비 수치·라이선스 검증은 이번 범위 밖이며 폰트 파일을 전달하지 않는다.
- UI-01의 큰 소개 제목보다 작업 제목을 작게 하여 영상·입력·CTA에 집중한다. 영상 패널과 조절 카드를 나란히 놓고, 버튼은 라임 주 행동/테두리 보조 행동으로 구별한다. 인위적인 광채·장식 수치·계측 HUD를 넣지 않는다.
- 비회원도 분석에 진입할 수 있는 현재 범위를 유지한다. 로그인 요구나 새 권한·결제 기능을 추가하지 않는다.

## 6. 이번 이미지에 넣지 않을 기능·자산

빈 드롭존, 감지 중/실패의 추가 화면, 여러 상태 콜라주, 모바일, 로그인 모달, 샘플 결과, 기록 목록, 분석 진행률, 점수/관절/궤적, AI 코칭, 감지 재시도 버튼, 새 API, 파일 업로드 완료 주장, 파일 크기/형식 검사 결과, 관리자·결제·CSV 기능을 넣지 않는다.

제안값 360px의 후속 재배치는 파일명·변경 → 영상 → 시작·끝·선택 길이 → 분석 → 개인정보 순서다. 긴 파일명은 줄바꿈하고 필수 입력을 숨기지 않는다. 브라우저·반응형·키보드·실제 분석/API는 실행하지 않으며 ISSUE를 해결로 닫지 않는다.

- APR-03 = `UI_STRUCTURE`, 대상 UI-02 구조 revision **2**. 기존 구조 revision 1에 ISSUE-01·03·06·11의 제안과 대표 상태·문구 계약을 구체화했다. 생성될 UI-02 r1 이미지의 승인이 아니다.
- state_revision **3 → 4**, UI-02 image revision **1**. UI-01과 APR-01·APR-02·ASSET-01은 보존, UI-03–08은 미생성 유지.
- 상태 기록에 남아 있던 UI-01 승인 대기·승인 없음 표현은 기존 APR-02 근거로만 정합성을 보완한다. 새 UI-01 승인을 만들지 않는다.
- D05-01 구조 동의 → D05-02 실제 승인 참고 확인 → D05-03 이 브리프 저장 → D05-04 대표 상태 한 개 고정 → D05-05 내장 이미지 도구 1회 → D05-06 대조 → D05-07 제시 순서. 생성 실패는 실패로 보고하고 다른 파일로 대체하지 않는다.

생성 목표 경로: `docs/planning/mockups/UI-02_r1.png` — 브리프 작성 시점에는 **미생성**. 생성 후 실제 파일·치수·SHA-256·차이만 별도 리뷰와 STATE에 기록한다. ASSET-02 상태는 성공 시 **GENERATED**, 승인 당시 해시는 null이다.

생성 후 연결: [실제 도구 입력](UI-02_r1.imagegen.txt) · [D05-06 대조 기록](UI-02_r1_review.md) · [시안](../mockups/UI-02_r1.png). 1회 생성에 성공했으며 출력 치수·영상 비율·배치·스타일 차이는 대조 기록을 따른다.
