## 1. 화면 목적 / 첫 행동 / 지원 기기와 화면 비율

비회원이 선택 파일과 분석 구간을 확인·조정한 뒤 **이 구간으로 분석 시작**을 누르는 UI-02. 대표 상태는 KO·밝은 테마·파일 선택 후 자동 감지 완료. 필요하면 `파일 변경`으로 교체한다. REQ-01·07·08·09에 연결한다.

데스크톱 **16:9 단일 화면**, 생성 목표 **2048×1152px**. 영상 내부 목표 **324×576px(9:16)**. 모두 배치 제안값이며 승인된 CSS 수치가 아니다. 실제 생성 치수·비율은 리뷰에 기록하고, 생성 원본을 임의 크롭·리사이즈하지 않는다. 빈 상태·감지 중·실패·모바일은 이번 이미지 밖이다.

## 2. 상단·주 영역·보조 영역·하단의 구체 배치

목표 캔버스 기준의 제안 좌표이며 출력 실측값이 아니다.

| 영역 | 배치 |
|---|---|
| 공통 상단 | 높이 약 96px, 흰 바탕. 왼쪽 굵은 `Swing.Lab`, 오른쪽 r2a 메뉴 순서. 로그인은 조용한 외곽선 버튼. |
| 제목·파일 행 | 본문 좌우 약 160px. `분석 구간 선택` 제목 아래 파일 아이콘+`일반.mp4`. 같은 행 오른쪽 `파일 변경`에 초점 표시 1개. |
| 왼쪽 미리보기 | x≈160, y≈308, 폭≈490, 높이≈746. 흰 면과 얇은 회청색 경계. 내부 x≈243, y≈340의 324×576 세로 프레임에 전신·클럽 실루엣, 옅은 파랑 배경, `이미지 예시`. 재생·탐색·0:01 / 0:08·음량은 영상 밖 아래 한 줄. |
| 오른쪽 조절 | x≈700, y≈308, 폭≈1188, 높이≈746. 옅은 파랑의 평평한 면과 절제된 모서리. 완료 상태 → 조정 안내 → 시작 → 끝 → 선택 길이 → 주 버튼 → 개인정보 순서. |
| 상태·입력 | 체크 아이콘+`스윙 구간 자동 감지 완료`, 아래 기존 안내. 같은 길이의 가로 슬라이더 2개, 위 행 왼쪽 라벨/오른쪽 수치. 0–8초 기준 손잡이는 15%와 60%. 색 외에도 아이콘·문자로 상태 구별. |
| 실행·하단 | 구분선 뒤 `선택 길이 3.6s`, 폭이 넓은 코발트 주 버튼, 아래 방패 아이콘+개인정보 전문과 밑줄 링크. 모든 내용이 한 화면에 보임. 별도 기록 띠 없음. |

재생 탐색 위치는 합성 시간 1/8=12.5%로 요청하며 구간 입력과 구별한다. 파일 변경의 초점은 남색 외곽선과 흰 간격으로 표시한다.

### 이미지에 동시에 넣지 않는 상태 문구

| 상태 | 문구와 근거 | 동작 계약 |
|---|---|---|
| 감지 중 | `스윙 구간 자동 감지 중...` — upload_detecting | 분석 비활성화, 상태 변경 알림 |
| 완료 | `스윙 구간 자동 감지 완료` 후보 + trim_hint 원문 | 이번 대표 상태, 제안 구간 수동 조정 |
| 감지 실패 | `자동 감지에 실패해 전체 영상이 선택됐어요. 슬라이더로 스윙 구간을 직접 정해 주세요` — **현재 trim_detect_failed** | r1의 옛 실패 후보를 대체. 파일·미리보기 유지, 실패 상태에 완료 안내를 함께 쓰지 않음. |
| 선택 전 | `파일 선택` 후보 / `MP4, MOV, AVI 파일을 드래그하거나 클릭해서 선택하세요` — upload_dropzone | 다음 revision 후보인 빈 상태용, 이번 미생성 |

현행 UploadTrim에는 이미 `role="button"`·tabIndex·Enter/Space, 감지 실패 분기, `role="status"`가 있다. r1의 ‘전혀 없음’ 설명은 현재 사실로 재사용하지 않는다. 선택 후 파일 변경 버튼과 range의 실제 label/id 연결은 여전히 후속 구현 대상이다. 이번에 코드를 수정하거나 ISSUE를 해결로 닫지 않는다.

파일 변경 취소 시 초안 유지, 새 파일 확정 시 이전 구간·감지 상태 초기화라는 r1 제안을 유지한다. 슬라이더 step=0.1초, 최소 간격=0.5초, 감지 중 또는 선택 길이 1초 미만일 때 분석 비활성화라는 현행 계약을 유지한다. 예시 3.6초는 활성 상태다. 접근 가능한 이름·초점·상태 알림·실제 동작은 구현 검수 대상이다.

## 4. 컴포넌트 형태·정보 밀도·색/글자 역할

승인 r2a에서 관찰한 밝은 스포츠 편집 디자인을 사용한다. 방향 A의 제안색은 흰색 `#FFFFFF`, 코발트 `#2448D8`, 짙은 남색 `#152040`, 옅은 파랑 `#ECF1FF`. 정확한 픽셀색 일치나 토큰 승인을 뜻하지 않는다.

굵은 현대 한국어 고딕의 제목과 남색 텍스트 브랜드, 여유 있는 본문 행간, 단정한 숫자. 시간도 r2a의 현대 고딕 계열로 통일하고 r1의 민트 등폭 계측 느낌은 계승하지 않는다. CTA는 흰 글자의 코발트 둥근 사각형, 보조 버튼은 남색 글자와 얇은 회청색 테두리. 패널은 밝고 평평한 면으로 구획하며 어두운 카드·네온·광채·그라데이션은 넣지 않는다. 실제 폰트 파일·라이선스 식별이나 대비 적합성 판정은 미확인이다.

## 6. 이번 이미지에 넣지 않을 기능·자산

빈 드롭존, 감지 중/실패 화면, 모바일, 콜라주, 결과/점수/관절/궤적, 기록 띠, AI 코칭, 로그인 모달, 새 API·재시도 버튼·숫자 입력·통합 이중 슬라이더·필름 스트립·파일 제한 수치를 추가하지 않는다. 비회원 분석 범위와 기존 기능을 유지한다.

모바일 재배치, EN 전환, 실제 파일 선택/교체, 방침 왕복 초안 보존, 분석/API, 서버 삭제, 키보드·보조기술·대비는 **NOT_RUN / 미확인**이다. 코드·빌드·커밋은 이번 작업 범위 밖이다.

## 7. 이번 기획의 현재 구조 revision

APR-03의 **구조 revision 2**와 APR-04의 r1 구조·문구 개선을 유지하되, APR-06의 UI-01 r2a 시각 언어로 UI-02 **image revision 2**를 생성한다. 새 시안은 승인되지 않았다. 이전 승인·자산 레코드와 파일을 변경하지 않는다.

D05-03 이 브리프 저장 → D05-04 완료 상태 1장 고정 → D05-05 내장 이미지 생성 → D05-06 대조·디코딩·SHA-256 → D05-07 제시 후 중지. 성공 시 STATE의 asset_records에 **ASSET-06 / GENERATED / 승인 ID null / 승인 당시 SHA-256 null**, state_revision **7→8**만 추가·갱신한다. 기존 screens의 r1 승인 참조는 과거 승인으로 보존하며 r2 승인이 아니다.
