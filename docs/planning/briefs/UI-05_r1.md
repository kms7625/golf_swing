## 1. 대표 상태와 범위

**KO / 밝은 코발트 / 비회원 / 촬영 중(capturing) / 관절 인식 및 영상 녹화 가능** 상태. 영상 위 관절 스켈레톤과 현재 각도 HUD, 녹화 상태 및 종료 행동을 한 화면에서 확인한다. 인물은 남색 전신 골퍼 일러스트이고 카메라 안에 **이미지 예시**, 각도 영역에는 **예시 수치**를 표시한다. 실제 카메라·분석 데이터가 아니다.

데스크톱 **16:9 한 장**, 목표 2048×1152px. 첫 뷰포트만 생성하며 다른 상태·모바일 이미지는 만들지 않는다. 출력 규격에 차이가 있으면 실제 치수를 대조 기록에 공개한다. 생성 결과를 코드로 크롭·리사이즈·글자 합성하지 않는다.

## 2. 배치와 정확한 문구

| 영역 | 배치·문구·역할 |
|---|---|
| 공통 상단 | 흰 바탕, 왼쪽 굵은 남색 `Swing.Lab`; 오른쪽 `실시간 캠`(코발트 활성 표시) → `내 기록` → 해 아이콘+`테마` → `KO / EN`(KO 밑줄) → 외곽선 `로그인`. |
| 제목 / 설명 | `실시간 웹캠 분석`. 아래 `기기에서 관절 움직임을 실시간으로 측정해요.` 기술 용어 ‘온디바이스’를 쉬운 말로 바꾼 NE-15 제안. |
| 왼쪽 카메라 | 주 작업 영역 약 58% 폭, 4:3 프레임. 밝은 옅은 파랑 연습 공간, 머리·양발·클럽이 모두 보이는 골퍼 한 명. 관절 연결선은 코발트, 점은 흰 중심+코발트 테두리. 어깨·팔꿈치·손목·골반·무릎·발목 위에 정렬. 작은 배지 `관절 인식 중`, 반대편 `이미지 예시`. 인식 배지는 이번 상태를 설명하는 UI 제안이다. |
| 영상 위 HUD | 영상 하단 안쪽 흰색 또는 거의 불투명한 밝은 패널. `실시간 각도`와 `예시 수치`, 세 열 `상체 기울기 32.4°` / `어깨선 기울기 18.0°` / `골반선 기울기 9.0°`. 값·단위를 붙여 두고 몸·발을 가리지 않게 인물을 배치한다. 수치의 정상/위험 판정이나 색 등급은 추가하지 않는다. |
| 오른쪽 상태 면 | 코발트 바탕, 큰 흰 `촬영 중`, 작은 원형 녹화 아이콘+`녹화 중`. `스윙이 끝나면 ‘촬영 종료’를 눌러 결과를 확인하세요.` 현재 단계가 실시간 점수·7단계 검출 완료처럼 보이지 않게 한다. |
| 촬영 준비 체크 | 흰 영역 제목 `촬영 준비`, 보조 `직접 확인한 준비 항목`. 체크된 상자 세 개와 `머리부터 발끝까지 화면 안에`, `클럽을 휘두를 공간 확보`, `준비 자세부터 마무리까지 한 번`. 사용자가 준비 상태에서 직접 확인한 항목을 촬영 중에도 보여주는 제안이며 자동 검증 배지가 아니다. |
| 종료 버튼 | 사각 정지 아이콘+`촬영 종료`, 충분히 큰 코발트 버튼·흰 글씨. 버튼 바깥 흰 간격과 남색 초점선이 별개로 보이도록 요청한다. 준비 상태의 `촬영 시작`은 이 촬영 중 이미지에 함께 표시하지 않는다. 현행은 시작이 측정과 녹화를 함께 시작하고 종료가 둘 다 끝낸다. 별도 녹화 일시정지 기능은 추가하지 않는다. |
| 후속 처리 안내 | 종료 버튼 아래 `종료 후 측정값을 서버로 보내 점수를 계산해요.` 다음 줄 `녹화 영상은 ‘정식 분석’을 누르면 업로드해요.` 두 동작의 전송 대상을 구별한다. |
| 이탈 | 보조 외곽선 `홈으로`. 근처 `화면을 나가면 촬영 내용이 사라져요.` 현행 onBack의 실제 홈 이동과 이름을 맞추는 제안. |

목표 배치: 헤더 약 90px, 제목·설명 y≈135–235px, 카메라 x≈80/y≈285/w≈1056/h≈792px, 오른쪽 x≈1200/w≈760px. 상태 → 체크 → 종료 → 처리 안내 → 이탈을 위에서 아래로 읽는다. 생성용 배치 제안이며 CSS 수치 승인이 아니다.

## 3. 실제 기능·문구 대조 / NE-15

읽은 코드: [LiveCapture.tsx](../../../web/src/components/LiveCapture.tsx) 전체, [i18n.tsx](../../../web/src/lib/i18n.tsx)의 라이브 문구, [geometry.ts](../../../web/src/lib/geometry.ts), [LiveCapture.module.css](../../../web/src/components/LiveCapture.module.css), [App.tsx](../../../web/src/App.tsx)의 live 연결, [api.ts](../../../web/src/lib/api.ts)의 scoreLive, [CLAUDE.md Live webcam analysis](../../../CLAUDE.md).

| 현행 근거 | 시안 해석 / 보존 사항 |
|---|---|
| `loading → ready → capturing → processing → done/error` | 대표 상태는 capturing 하나. 실시간 각도 측정과 종료 후 결과를 구별하며 촬영 중 총점·등급·7단계 타임라인은 그리지 않는다. |
| HUD는 SPINE / SHOULDER / HIP 3개. 무릎·팔꿈치도 계산·버퍼링하지만 HUD에는 없음 | 세 항목을 유지하고 표시 이름만 쉬운 한글로 바꾼다. 임의의 추가 지표·실시간 코칭·정확도·프레임 속도·타이머는 넣지 않는다. |
| `angles.spine` = `calcSpineAngle` | `상체 기울기`: 영상에서 어깨 중심–골반 중심선이 수직선과 이루는 각도. UI-04의 ‘척추각 변화’(구간 변화량)와 다르다. |
| `angles.shoulderRotation` / `angles.hipRotation` | `어깨선 기울기` / `골반선 기울기`: 영상에서 양쪽 어깨선/골반선이 수평선과 이루는 각도. 3D 몸통 회전각·최대 회전·X-Factor로 부르지 않는다. |
| 각도 표시는 KEY_JOINTS 가시성 통과 때 갱신 | 현재 판정은 어깨·골반·무릎이며 머리·발끝·클럽 포함을 자동 보증하지 않는다. 준비 체크는 반드시 사용자 직접 확인으로 구별한다. 관절 미검출 때 과거 angles를 비우는 분기는 없어, 미검출 표시·값 비우기는 후속 구현 제안이다. |
| MediaRecorder는 가능한 환경에서 측정 시작과 동시에 녹화 | 이 시안은 실제 녹화 가능 환경을 가정한다. `녹화 중` 표시는 단순히 capturing이면 항상 붙이는 구현 계약이 아니며 recorder 성공 상태에 연결해야 한다. |
| 종료 후 손목 Y와 프레임별 각도를 `/score-live`로 전송 | 관절 계산은 기기에서 하지만 전체 기능이 오프라인·서버 전송 없음이라고 표현하지 않는다. 모델 준비에도 네트워크가 필요하다. `/detect-phases`가 현행 라이브 완료 경로라고 쓰지 않는다. |
| recordedBlob이 있는 done 상태에만 정식 분석 버튼 | 결과·코칭을 얻는 라이브 처리와 영상 업로드로 얻는 정식 분석·저장·비교를 구별한다. 정식 분석 버튼은 촬영 중에는 표시하지 않는다. |
| 영상과 canvas 모두 `object-fit: cover` 및 좌우 반전 | 후속 구현에서도 같은 크기·크롭·반전을 적용해 관절 위치를 맞춘다. 정적 실루엣의 정렬은 실제 카메라 정렬 검증이 아니다. |

32.4 / 18.0 / 9.0은 표시 설계를 위한 합성값이며 일러스트에서 계산한 값이 아니다. 현행 계산·임계값·API·코어·단계 검출을 변경하지 않는다. 화면의 신규 문구·한글 HUD는 후보이며 KO/EN i18n 등록은 구현하지 않는다.

## 4. 준비·오류·완료 상태별 계약 / NE-20·ISSUE-10

이 표는 **후속 구현 제안**이다. 현재 준비 체크·원인별 재시도·재촬영·업로드 대안이 구현됐거나 이번 이미지에 모두 그려졌다는 뜻이 아니다.

| 상태 / 현행 사실 | 안내 문구 후보 | 행동·복구·보존 제안 |
|---|---|---|
| 화면 모듈 로딩 / App spinner | `촬영 화면을 불러오는 중이에요.` | 로딩 중 중복 시작 막기. 모듈 로딩 실패 시 `촬영 화면을 다시 불러오기`, `영상 업로드`(UI-02), `홈으로` 제공. 오류 경계와 실제 재로딩 방식은 후속 구현 대상. |
| 모델 준비 / 현행은 모델 로드 후 카메라 요청 | `움직임 인식 기능을 준비하고 있어요. 인터넷 연결이 필요해요.` | 모델 준비와 권한 요청을 구별. 완료 전에 촬영 시작 잠금. 예상 완료 시간은 표시하지 않는다. |
| 카메라 권한 요청 대기 | `카메라 사용을 허용해 주세요.` | 사용자가 응답하기 전 ‘거절’로 분류하지 않는다. `영상 업로드`, `홈으로` 대안. |
| 권한 거절 / 현재 일반 error | `카메라 권한이 꺼져 있어요. 브라우저의 사이트 설정에서 카메라를 허용해 주세요.` | 설정 변경 안내 → `카메라 다시 연결`, `영상 업로드`. 권한을 버튼이 자동으로 바꿀 수 있다고 약속하지 않는다. 권한 허용 후 같은 화면 준비 상태로 복귀. |
| 카메라 없음·다른 앱 사용·접근 불가 / 현재 일반 error | `카메라에 연결할 수 없어요. 연결 상태와 다른 앱의 사용 여부를 확인해 주세요.` | `카메라 다시 연결`, `영상 업로드`, `홈으로`. 지원되지 않는 접근 환경도 원인 확인 후 별도 안내하며 특정 브라우저 호환을 단정하지 않는다. |
| 모델 다운로드·초기화 실패 / 현재 일반 error | `움직임 인식 기능을 준비하지 못했어요. 인터넷 연결을 확인하고 다시 시도해 주세요.` | `인식 기능 다시 준비`로 재초기화, `영상 업로드` 대안. 반복 실패 시 현재 촬영 불가를 명시. 원시 예외를 그대로 노출하는 대신 작업 중심 문구로 변환하는 제안. |
| 준비 완료 ready | `촬영 준비를 확인하고 시작하세요.` | §2의 세 항목을 체크박스로 제공. 사용자 직접 확인이며 자동 검증·측정 정확도 보증이 아님. `촬영 시작` → capturing; 같은 체크 상태를 촬영 중 유지. 검증 안 된 거리·촬영 각도·최소 초 수는 강제하지 않는다. |
| 촬영 중·녹화 가능 / 이번 한 장 | `촬영 중`, `녹화 중`, `관절 인식 중` | `촬영 종료`로 녹화 청크 마감 후 측정값 처리. 종료의 중복 실행 방지는 후속 구현 조건. |
| 최초 미인식·도중 인식 손실 / 현행 이전 HUD가 남을 수 있음 | `몸이 잘 보이지 않아요. 전신이 화면 안에 들어오도록 조정해 주세요.` | 실시간 값은 `—`, `관절 확인 필요`로 바꾸어 이전 값과 현재 값을 혼동하지 않게 함. 녹화 여부와 인식 여부를 별도로 유지. 종료 가능. 회복 때 현재 값으로 갱신. |
| 녹화 미지원·녹화 시작 실패 / 현행 라이브 점수만 가능 | `영상 녹화는 사용할 수 없어요. 실시간 측정과 종료 후 점수 확인은 가능해요.` | `녹화 중` 표시 금지. `정식 분석용 영상은 만들어지지 않아요.`를 시작 전/촬영 중 알림. 완료 후 `영상 업로드` 대안. |
| 촬영 자료 부족 / 현재 유효 프레임 20개 미만이면 ready | `분석할 움직임이 부족해요. 전신이 보이도록 준비 자세부터 마무리까지 다시 촬영해 주세요.` | 세 체크를 다시 보이며 `다시 촬영`. 20개 조건은 초 단위 촬영 시간과 동일하지 않다. 새 촬영 시작 시 이전 버퍼·녹화본 교체를 안내. |
| 종료 후 처리 중 | `촬영을 마쳤어요. 측정값으로 점수를 계산하고 있어요.` | 종료 중복 실행 잠금. 녹화본과 측정값을 세션 안에 보유한다는 후속 계약. 완료 전 점수·7단계 결과를 미리 그리지 않음. |
| 점수 계산 실패 / 현재 일반 error, 트랙 정지 | `촬영은 끝났지만 점수를 불러오지 못했어요.` | 남은 측정값으로 `점수 다시 계산`, 녹화본이 있으면 `이 영상으로 정식 분석`, `다시 촬영`, `영상 업로드`. 녹화본·버퍼를 실패 안내 중 버리지 않도록 하는 제안. |
| 완료 done | `촬영 결과`, 점수·지표·진단·파형·코칭 | `다시 촬영`은 카메라/모델 준비를 다시 거쳐 ready로. 녹화본이 있을 때 `이 영상으로 정식 분석` → UI-03 → UI-04. 코칭 로그인 분기는 현행 유지. |
| 녹화본 없음·빈 녹화본 | `녹화 영상이 없어 정식 분석으로 이어갈 수 없어요.` | 점수 등 이미 얻은 결과는 유지하며 `다시 촬영`·`영상 업로드` 대안. 단순히 버튼만 숨기지 않는다. |
| 정식 분석 실패 / 현재 App에서 UI-02 복귀 | `정식 분석을 완료하지 못했어요.` | 녹화본 초안을 세션 내 보존해 재시도 또는 촬영 결과 복귀할 수 있도록 UI-03과 함께 설계. 현재 LiveCapture unmount 이후 보존은 미구현이며 복구된다고 단정하지 않는다. |
| 홈·상단 메뉴·새로고침·닫기 | `화면을 나가면 촬영 내용이 사라져요.` | 촬영 중 앱 내 이탈에는 `계속 촬영` / `촬영을 버리고 이동` 선택 후보. 트랙·모델·녹화 종료와 늦은 응답 무효화는 후속 구현. 새로고침·닫기 후 자동 복구·영구 보관은 약속하지 않는다. |

## 5. 시각·접근성·좁은 화면 제안

흰 #FFFFFF 배경, 남색 #152040 고딕, 코발트 #2448D8 상태 면·주 행동, 옅은 파랑 #ECF1FF 보조 면과 구분선을 사용한다. UI-04처럼 굵고 명확한 위계와 작은 모서리를 유지한다. 녹화는 작은 적색 원+글자로 구별하고 빨강을 각도 판정에 쓰지 않는다. 관절은 코발트 선·흰 중심 원으로 남색 인물과 구별한다.

촬영 준비 체크는 자동 전신 검증과 혼동하지 않도록 ‘직접 확인’이 항상 보인다. 각도는 소수점 한 자리와 °, 상태는 글자와 기호를 함께 제공한다. 후속 구현 시 촬영/종료/복구 버튼의 키보드 접근, 입력 라벨, 초점 표시, 오류/상태 변경 알림을 확인한다. 프레임마다 스크린리더로 각도 숫자를 알리는 동작은 제안하지 않는다.

360px은 구조 문서의 제안 폭을 계승한다. 좁은 화면에는 영상 → 촬영 종료 → 현재 인식 상태 → 영상 밖 각도 요약 → 준비/전송 안내 순서로 배치하고, 오류·종료 버튼을 숨기지 않는다. 이번 이미지로 모바일·실기기·가독성·대비 적합성을 인증하지 않는다.

## 6. 생성·검증·보존·보고

내장 image_gen으로 신규 시안 한 장을 생성한다. 승인 4장은 실제 열람 후 텍스트로 시각 특징을 전달하며 신규 호출에 편집용 이미지 참조 인자를 넣지 않는다. 정확한 입력은 [UI-05_r1.imagegen.txt](UI-05_r1.imagegen.txt), 최종 PNG는 [UI-05_r1.png](../mockups/UI-05_r1.png), 육안 대조·치수·SHA-256과 차이는 [UI-05_r1_review.md](UI-05_r1_review.md)에 기록한다.

STATE 18→19에서 APR-11(UI_STRUCTURE), 19→20에서 ASSET-13(GENERATED)을 추가한다. ASSET-13의 approval_id·approval_sha256_or_null은 null. 기존 승인·자산·결정·기타 JSON 필드와 역사 문장은 보존하고 최신 검토 안내를 맨 위에 추가한다.

직접 작성·복사하는 파일은 docs/planning/ 아래 STATE·브리프·생성 입력·대조 기록·PNG 5개로 한정한다. 내장 이미지 도구가 자체 관리하는 캐시 원본은 도구 동작과 구별해 기록한다. 코드 수정·커밋·UI_IMAGE 승인 생성은 하지 않는다.

golf-ui-ux B1–B6 검토: API·대표 프레임·샘플 계약 보존, 문자열은 문서 후보만 작성, 판정 기준·제외 기능 추가 없음. **NOT_RUN**: 앱 실행·카메라·모델·녹화·서버 분석·빌드·코드 테스트·브라우저·키보드·보조기술 시험. 파일 검증은 PNG 디코딩·해시·상태 파싱·기존 기록 보존·쓰기 범위 대조로 한정한다.

사용자 지시대로 결과 보고 후 **“UI-05 r1 시안을 승인하시겠어요, 수정 요청하시겠어요?”** 질문 하나를 남기고 멈춘다. 스킬이 요구한 추가 허가 절차가 아니라 [지정 지시 §1.5·§2](../codex-ui05-prompt.md)에 따른 검토 대기다.
