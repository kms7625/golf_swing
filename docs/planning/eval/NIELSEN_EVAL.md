### 1.3 집계 규칙

ISSUE-NE-01–25는 이 파일 안의 평가 관찰 ID이다. 기존 ISSUE를 다시 등록하거나 STATE에 채택한 ID가 아니다. 같은 관찰이 여러 원칙·화면에 등장해도 1건으로 센다. 기존 ISSUE의 묶음은 유지하며, ISSUE-06은 샘플 진행과 자동 감지 복구라는 서로 다른 작업 상황을 구분했다.

**25건 = 신규 7건 + 기존 중복·보강 18건.** 기존 18건 중 13건은 ISSUE-01–12와 연결되고, 5건은 ISSUE 번호가 없지만 기존 UI 구조 카드에 이미 적힌 문제다. 카드 기언급을 신규로 부풀리지 않았다.

| 심각도 | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| 고유 문제 수 | 0 | 0 | 21 | 4 | 0 |

아래 표의 0은 해당 확인 항목에 문제가 발견되지 않았다는 제한적 관찰이며 문제 수에 포함하지 않는다. 증거가 부족하면 숫자 대신 ‘미확인’으로 표시한다. 여러 관찰을 인용한 셀의 심각도는 최댓값이다.

## 3. 고유 발견과 D14 ISSUE 제안

아래는 D14 §7의 필드(위치·관련 ID·심각도·실제 문제·재현 입력·예상/실제·영향·담당·해결·회귀 TEST·상태)를 묶은 표다. **모든 행의 상태는 OPEN / 제안**이며, 기존 ISSUE를 FIXED/VERIFIED로 바꾸지 않는다. 관련 INT·TASK는 이번 지시에서 별도 지정되지 않아 해당 없음이다.

재현 입력은 후속 TEST용 제안이다. ‘실제’는 직접 확인한 이미지 또는 코드 분기를 뜻하며 해당 장애를 브라우저에서 재현했다는 뜻이 아니다. D14 분류는 현재 범위의 우선순위 제안으로, Nielsen 3을 MAJOR, 2를 MINOR로 정리했다. 두 척도를 일반적으로 동일시하는 규칙은 아니며 BLOCKING이나 출시 판정은 내리지 않는다.

## 4. 현재 앱 vs 승인 시안 UI-01 r1

이 비교는 동일한 역할의 첫 화면을 대상으로 한다. 현재 데스크톱 캡처는 1440×900, 시안은 1672×941이므로 배치의 가시적 차이를 동일 뷰포트에서 측정한 개선률로 해석하지 않는다.

브리프의 ‘첫 버튼에서 파일 선택’은 아직 구현되지 않은 행동 계약이다. 시안의 버튼 그림은 실제 동작을 확인할 수 없으며, 현재 App:144는 여전히 UI-02로 화면만 이동한다.

UI-02 r1은 처음에는 없었지만 최종 확인 중 실제 파일이 생성되어 평가에 포함했다. 현재 demo_구간선택.jpg와 비교하면 파일명·파일 변경·명시적 감지 완료 상태가 추가됐다. 이는 NE-03·14의 일부 표현 개선이며 초안 보존·실패 복구·키보드 작동을 해결했다는 증거는 아니다. 이미지 승인 대기라는 상태를 유지하며 UI-01 승인과 구별한다.
