# Codex 작업 지시 — Swing.Lab 비주얼 에셋 (이미지 생성 + 아이콘 + 장식)

## 0. 먼저 읽을 것
1. `docs/codex-redesign-prompt.md` — 이전 리디자인 지시서. **3절 규칙 R1~R10은 이번에도 그대로 적용**(아래 R1만 확장)
2. `docs/redesign-proposal.md` — 확정된 시안 A "Club Lime"의 토큰 표
3. `web/src/index.css` — 현재 토큰(다크: 배경 `#111610`, 라임 `--copper` `#C5F26B`, 민트 `--teal` `#73DACC` / 라이트: 배경 `#F6F8EF`, 딥그린 `#416500`)
4. `web/src/components/Hero.tsx`, `Hero.module.css` — 현재 첫 화면의 SVG 막대 인형(교체 대상)
5. `docs/screenshots/hero.jpg`, `result.jpg` — 현재 화면

## 1. 목적
현재 첫 화면의 막대 인형 SVG가 디자인 완성도를 떨어뜨린다. Club Lime 디자인에 어울리는 **생성 이미지**로 교체하고, 앱 전반에 아이콘과 장식을 더해 완성도를 올린다. 중간발표(2026-10-15) 데모 화면에 쓰이므로 **기능·흐름·API는 바꾸지 않는다.**

## 2. 진행 방식 — 2단계, 1단계 끝에서 반드시 멈춘다

### 1단계: 시안 생성과 배치 계획 (앱 코드 수정 없음)
- 이미지 생성 도구로 아래를 만들어 `docs/visual-candidates/`에 저장:
  - **첫 화면 그림 시안 2개**(H1, H2): 골프 스윙 중인 인물 + 관절 추적 점·선(라임/민트) 오버레이. 실존 인물·브랜드 로고·글자 금지. 실루엣이나 양식화된 표현으로 특정인처럼 보이지 않게
  - **빈 상태 그림 시안 1개**(E1): 업로드 전 화면, 스윙 기록이 없을 때 쓰는 작은 그림
- 다크·라이트 두 배경 모두에서 어울려야 한다 → **투명 배경 PNG**로 생성하거나, 테마별 2장으로 만든다
- `docs/visual-plan.md` 작성:
  - 각 시안 미리보기 경로, 사용 위치, 크기
  - 아이콘 목록(SVG로 직접 작성할 것): 사용 위치, 의미, 한 줄 설명
  - 그 밖의 장식 제안(배경 그라데이션·패턴·카드 강조 등) 최대 5개, 각각 "어느 화면 / 무엇이 달라지나 / 예상 변경 줄 수"
  - 추천 조합 1개 + 이유 2문장
- **여기서 멈추고 사용자 선택을 기다린다.**

### 2단계: 선택된 조합 적용 (사용자 선택 후에만)
- 선택된 이미지를 WebP로 변환해 `web/public/images/`에 둔다(첫 화면 1장 ≤ 250KB, 빈 상태 그림 ≤ 80KB, 전체 추가 용량 ≤ 600KB)
- `<img>`에 `width`·`height`를 지정해 레이아웃이 흔들리지 않게 하고, 첫 화면 외 이미지는 `loading="lazy"`
- 첫 화면의 계측 수치(SPINE / SHOULDER / FRAME)는 **이미지에 굽지 말고 HTML 텍스트로 이미지 위에 유지**한다
- 아이콘은 `web/src/components/icons.tsx` 하나에 SVG 컴포넌트로 만들고 색은 `currentColor`로 테마를 따른다

## 3. 규칙
| # | 규칙 |
|---|---|
| R1 | 수정 가능 경로: 이전 지시서 R1 허용 경로 + `web/public/images/`(신규) + `web/src/components/icons.tsx`(신규) + `docs/visual-candidates/`·`docs/visual-plan.md`(신규) |
| R2 | 이전 지시서 R2~R10 그대로(서버·분석 코드·`types.ts`·`status.ts`·샘플 변경 금지, npm 패키지 추가 금지, 토큰만 사용, KO·EN 문자열 동시 추가, 상태는 색만으로 구분 금지, 대비 AA, 애니메이션은 `prefers-reduced-motion`에서 끔, `LiveCapture` lazy-load 유지, 화면 흐름 변경 금지) |
| R3 | 이미지 대체 텍스트(`alt`)는 i18n에 KO·EN 둘 다. 장식용 이미지는 `alt=""` + `aria-hidden` |
| R4 | 이미지 변환에 새 패키지를 설치하지 않는다. macOS 기본 `sips` 또는 이미 있는 도구만 쓴다. WebP 변환이 불가능하면 최적화한 PNG로 두고 보고한다 |
| R5 | **git 커밋하지 않는다**(샌드박스가 `.git` 쓰기를 막는다). 대신 마지막 보고에 "커밋 묶음 제안"(묶음별 파일·메시지·예상 줄 수, 묶음당 200줄 이하)을 적는다 |

## 4. 완료 기준 (2단계 후, 직접 실행해 확인)
1. `cd web && npm run build` exit 0
2. `cd web && npm run lint` exit 0, 경고 수가 작업 전(18개)보다 늘지 않음
3. `git status --short`의 변경 파일이 R1 허용 경로 안에만 있음
4. `web/public/images/` 파일 크기가 2단계 상한 이내(`ls -la`로 확인)
5. 빌드 결과에서 `LiveCapture`가 별도 청크로 유지
6. 브라우저 확인이 가능하면: 360px·390px·1440px에서 가로 스크롤 없음, 다크·라이트 양쪽에서 이미지가 배경과 어울림. 못 하면 "미확인"

## 5. 마지막 보고 형식
- 완료 기준 1~6 각각 PASS/FAIL/미확인 + 근거
- 생성한 이미지 목록(경로·크기·용량)과 사용한 생성 프롬프트 원문 — AI 활용 과정 보고서에 그대로 쓰인다
- 커밋 묶음 제안
- 확인 못 한 것은 "미확인" — 확인하지 않은 것을 통과로 쓰지 않는다
