## 해석
1. **임팩트 검출은 이미 실용 수준**(87.3%, 오차 중앙값 1프레임)
2. **톱은 체계적으로 약 2프레임 이르다.** 앱은 "손목 최고점", GolfDB Top은 "백스윙 정점(클럽 기준)" — 손목이 클럽보다 먼저 정점에 도달하는 것과 일치하는 방향. 진단용으로 예측을 +2프레임 옮기면 PCE 29.0% → 79.2%(+1: 68.6%, +3: 66.9%). **단 이 수치는 같은 데이터로 맞춘 값이라 그대로 성능이라 할 수 없다** — 보정을 적용하려면 GolfDB 분할(split 1~4)로 한쪽에서 정하고 다른 쪽에서 검증해야 함
3. **Address·Finish는 정의 불일치가 크다.** 앱의 "백스윙 시작"·"피니시 구간 시작"은 GolfDB의 Address(테이크어웨이 직전)·Finish(스윙 종료 정지)와 다른 순간. 정확도 문제라기보다 이벤트 정의를 GolfDB에 맞출지의 결정 사항
4. 중간 집계(111개)에서 "Address를 평균 39프레임 이르게 잡는다"고 보고했으나, 전체 246개에서는 **늦게 잡는 경우가 63%**로 방향이 섞여 있음 — 평균이 일부 큰 이탈값에 끌린 결과였다. 정정한다

## 한계
- 160×160 저해상도 · 바운딩박스 크롭 · 프로 선수 YouTube 영상 — 스마트폰 원본·아마추어 영상의 성능과 다를 수 있음
- 앱 7구간 중 4개 시점만 비교 — GolfDB 8이벤트 PCE(SwingNet 76.1%, 증강 없이 71.5%)와 숫자를 직접 비교할 수 없음
- 허용 오차가 대부분 1프레임(30fps 기준 약 0.03초)이라 매우 엄격함 — "5프레임 이내" 지표를 함께 봐야 함
