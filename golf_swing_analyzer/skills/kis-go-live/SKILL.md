# KIS 실전 전환 — Go-Live 오케스트레이션

## 이 스킬의 역할과 한계

실전 전환은 여러 스킬에 걸친 작업(판정→앱키→설정→코드→검증)이며 실자금 리스크가 있는
**비가역 작업**이다. 이 스킬은 직접 판정하거나 코드를 고치지 않는다 — `실전전환_체크리스트.md`
(단일 진실 원천)를 단계별로 실행하되, **각 단계 사이에 사용자 승인을 강제**하고,
게이트 미충족 시 전환을 중단시키는 것이 유일한 책임이다.

## 절대 규칙

1. **선행 게이트 미충족이면 어떤 전환 작업도 시작하지 않는다** — "일단 준비만"도 금지
   (설정을 반쯤 바꾼 상태가 최악의 리스크). 게이트 현황 보고 후 종료.
2. **단계당 1승인** — 아래 각 단계 완료 시 결과를 보고하고 사용자의 명시적 "다음 진행"을
   기다린다. 여러 단계를 한 턴에 묶어 실행하지 않는다.
3. **전환 당일 장중(09:00~15:30) 작업 금지** — 반드시 장 외 시간.
4. 롤백 경로를 먼저 확보하지 않은 단계는 실행하지 않는다.

## 단계 (실전전환_체크리스트.md ①~⑦ 매핑)

### 0단계: 게이트 판정 (읽기 전용 — 언제든 실행 가능)
- 실측 SELL ≥ 30건 (`SELECT COUNT(*) FROM trades WHERE action='SELL'`)
- kis-strategy-review 합격 판정 (5인 패널) + 실측 손익비가 백테스트 기준(model_version) 대비 30% 이내 괴리
- 미충족 시: 현황 표(부족분 포함)만 보고하고 종료 — "리허설" 요청이어도 0단계까지만

### 1단계: 사전 준비 확인 (체크리스트 ②)
- 실전 앱키 확보 상태 확인 (KIS_REAL_APP_KEY가 주문 넣을 실전 계좌와 연결됐는지 사용자 확인 필수 — 코드로 검증 불가)
- 토큰 클라이언트 공유(kis_api.py, 커밋 44268d5)는 해결 완료 — 추가 작업 불필요

### 2단계: 코드 선행 작업 (체크리스트 ⑦ 중 전환 전 필수)
- **주문 TR-ID 교체** (0801U/0802U → 매도 0011U/매수 0012U) — kis-code-change로 위임 (A3 명세 대조)
- MAX_POSITIONS 5→3 (config.py), MAX_STOCKS 200→100 (watchlist.py) — kis-code-change로 위임

### 3단계: 설정 전환 (체크리스트 ③④)
- .env: KIS_MOCK=false / 계좌번호 / KIS_APP_KEY·SECRET 실전 키 / INITIAL_CAPITAL=실전 투입 자금 — kis-param-update로 위임 (.env·config 동시 확인 원칙)
- token_mock.json·token_real.json 삭제

### 4단계: 검증 (체크리스트 ⑤ — 장 외 시간)
- get_balance()가 실전 잔고 반환 (모의 5억이 나오면 즉시 3단계 롤백)
- dashboard "🔴 실전투자" 표시 / trader.log "모의투자:False"
- 다음 개장일 최소 1주 수동 테스트 주문 → 체결·[체결] 로그·잔고 반영 확인 후에만 자동매매 개시

### 5단계: 전환 후 정리 (체크리스트 ⑦ 잔여)
- 실현손익(TTTC8494R)·기간손익(TTTC8708R) 등 실전 전용 API 적용 — kis-code-change로 위임
- CLAUDE.md "모의투자 vs 실전 파라미터" 표·관련 문서 갱신

### 롤백 (체크리스트 ⑥ — 어느 단계서든)
stop_trader.ps1 → .env 원복 → 토큰 삭제 → 모의 잔고 확인 후 재시작.
**실전 보유 포지션이 있으면 수동 정리 전에는 롤백하지 않는다.**

## 출력 형식

```
[게이트 현황] SELL n/30 / 합격 판정 / 괴리 — 통과·미충족
[현재 단계] 0~5 중 위치
[이번 턴 수행] 수행 내용 + 위임한 스킬
[검증 결과] 해당 시
[다음 단계 진행 조건] 사용자 승인 대기 항목 명시
```
