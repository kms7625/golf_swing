## 결과를 받으면 먼저 확인할 것

### 1. 룩어헤드 바이어스 점검

`strategy.py get_signal()`이 `backtest=True`로 호출됐는지 확인.
- 근거: strategy.py L.82-88 (`backtest: bool = False` 파라미터 + docstring)
- `backtest=False`(기본값)로 실행된 결과라면 pump_detector·override·뉴스·공시 신호가
  "현재 시점" 기준으로 과거 데이터에 적용된 것 → **결과 무효, 재실행 필요**

신호 T일 종가 → 체결 T+1일 시가 룩어헤드 방지 적용 여부도 확인:
- 근거: backtester.py L.200-201 (`price = row["open"]  # T+1 시가 체결`)
- run_backtest_enhanced()도 동일 — backtester.py L.317-318

### 2. 비용 반영 점검

왕복 비용 0.21%(매수 0.015% + 매도 0.015% + 거래세 0.18%) 포함 여부를 명시한 뒤 해석.
- 근거: config.py L.52-54, backtester.py L.141-145 (`_calc_fee()`)
- 비용이 빠진 결과는 실제보다 낙관적

### 3. 백테스트 vs 실측 구분

두 종류를 절대 섞지 않는다. 표로 분리해서 보여준다:

```
| 구분 | 승률 | 손익비 | 기댓값 | 거래수 | MDD |
|---|---|---|---|---|---|
| 백테스트 (기간: ...) | ... | ... | ... | ... | ... |
| 실측 (누적, 기간: ...) | ... | ... | ... | ... | ... |
| 차이 | ... | ... | | | |
```

실측 거래수 30건 미만이면 "신뢰도 부족 — 추가 데이터 필요" 경고 필수.
실측 조회: `SELECT pnl FROM trades WHERE action='SELL'` (database.py L.166-175 `get_win_rate()`)

**실측 price 시대 구분 (해석 필수 주의)**: trades.db의 `price`는
2026-07-03 이후 거래 = **실제 체결가** (ODNO 체결조회, 실패 시 신호가 폴백),
그 이전 거래 = **주문 시점 현재가** (체결 슬리피지 미반영).
두 시대가 혼재된 집계로 슬리피지를 논하지 말 것 — 필요 시 ts 기준으로 분리 분석.

## 수치 분석 필수 출력 항목

```
기댓값 = (승률 × 손익비) - (패율 × 1)
```

빠짐없이 계산해서 출력:
- 기댓값, 손익비, 승률, MDD, 거래수
- evaluate.py 합격 기준(기댓값>0, 손익비≥1.5, MDD≥-5%, 거래≥30건) 대비 PASS/FAIL/WARN
  - 근거: evaluate.py L.36-40
- CLAUDE.md "확정 파라미터" 현재 기준값 대비 비교
  (기준값은 CLAUDE.md에서 확인 — 스킬 내 수치는 낡을 수 있으므로 항상 CLAUDE.md 참조)

## 섣부른 결론 금지

- "개선됐다" → 기댓값·손익비·거래수 종합 비교 먼저
- "좋아 보인다" → PASS/FAIL 기준 명시 후
- 거래수 5건 이하 → "통계적으로 무의미, 결론 유보"
- 강세장 구간 단독 결과 → 과최적화 의심 경고 필수
