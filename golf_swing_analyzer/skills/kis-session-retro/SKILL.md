# KIS 세션 회고 — 대화 지식 영속화

## 목적

이 프로젝트는 작업마다 즉시 커밋하므로 대부분의 지식은 이미 기록돼 있다.
회고의 역할은 **"빠진 것만 줍는 것"** — 대화 중 확정됐지만 커밋·문서·메모리
어디에도 안 남은 지식을 찾아 영속화한다. 전례: 커밋 f3fa2da (세션 회고 —
대화로만 존재하던 지식 4건 문서화).

같은 내용을 재기록하면 문서만 부푼다. **기록 전에 반드시 당일 git log와
CLAUDE.md, 메모리 인덱스를 확인**해서 이미 있는 것은 건너뛴다.

## 수집 대상 (이 5종만 — 대화를 훑으며 추출)

1. **확정 판정과 이유** — 유지/기각/보류 + 재검토 조건 (예: 하락장 필터 유지 판정)
2. **검증으로 확정된 사실·수치** — 로그 재현, 실측 대조로 굳어진 사실
   (예: 국면 판정은 하루 1회라 장중 반등에도 당일 매수 재개 안 됨)
3. **설계 결정과 채택 이유** — 왜 이 방식을 골랐고 어떤 대안을 버렸는지
   (예: 관찰 시점을 60초 루프가 아닌 16:00 배치로 정한 유량 근거)
4. **새로 발견된 알려진 한계·오탐 패턴** — 재발 시 오판을 막을 지식
   (예: PS5.1 `*>` 리다이렉션은 UTF-16 저장 — 파이썬 UTF-8 읽기 깨짐)
5. **운영 절차·워크플로우 변경** — 사람의 루틴이 바뀐 것
   (예: 아침점검 자동화로 세션 예약 불필요)

수집 대상이 아닌 것: 일회성 조회 결과, 그날만 유효한 시황, 코드 diff 자체
(git이 이미 보관), 진행 중이라 결론 안 난 논의.

## 저장소 라우팅 (지식 유형 → 목적지)

| 지식 유형 | 목적지 |
|---|---|
| 코드·아키텍처 사실, 알려진 한계·오탐 패턴 | CLAUDE.md 해당 섹션 (모듈 설명 / 주의사항) |
| 전략 판정 | CLAUDE.md "전략 확장 검토 이력" 또는 "파라미터 변경 이력" 표 |
| 점검 판정 기준, 인프라 원칙 | 해당 스킬 파일 (kis-daily-monitor, kis-ops-infra 등) |
| 진행 상태·검증 대기·사용자 선호 | 메모리 (~/.claude 쪽 — git 아님, MEMORY.md 인덱스 동기화) |
| 재사용 프롬프트·체크리스트 | 프로젝트 파일 (morning_check_prompt.md 전례) |

잘못 넣으면 낡거나 못 찾는다. 특히:
- **수치 하드코딩 금지** — 빠르게 낡는 수치(SELL 건수, 시나리오 일수 등)는
  값 대신 조회 방법을 기록 (CLAUDE.md "문서에 수치 하드코딩 금지" 원칙)
- 스킬 신설·개정이 생기면 CLAUDE.md "스킬 참조" 표와 kis-prompt-engineer
  스킬 지도를 함께 갱신 (라우팅 동기화 전례: 커밋 00bf22d)

## 절차

1. 당일 git log(`git log --oneline --since=midnight`)와 CLAUDE.md, 메모리
   인덱스를 훑어 "이미 기록된 것" 목록을 만든다
2. 대화를 시간순으로 훑으며 수집 대상 5종을 추출하고, 1의 목록과 대조해
   미기록 항목만 남긴다
3. 항목별로 라우팅 표에 따라 기록하고 **항목별 개별 커밋·푸시** (한국어 메시지)
4. 미기록 항목이 없으면 "회고 결과: 전부 기록돼 있음"으로 종결 — 억지로
   기록거리를 만들지 않는다

## 출력 형식

```
[회고 범위] 세션 주제 1줄
[이미 기록됨] 커밋/문서 대조 결과 n건 (나열은 간단히)
[미기록 발견] n건 — 항목·유형·목적지
[기록 완료] 커밋 해시 나열 (또는 "기록할 것 없음")
```
