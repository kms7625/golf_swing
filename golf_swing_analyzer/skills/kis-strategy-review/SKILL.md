# KIS 전략 합격 판정 — Trading Council

## 언제 이 스킬을 쓰는가

전략의 합격 여부나 파라미터 변경의 타당성을 묻는 모든 요청.
코드 구현이 아니라 **판단**이 목적인 경우.

---

## 합격 기준 (evaluate.py L.36-40과 동일)

```
기댓값 = (승률 × 손익비) - (패율 × 1)   ← 반드시 계산 후 출력
```

| 항목 | 기준 | 미달 판정 |
|---|---|---|
| 기댓값 | > 0 | ❌ 즉시 불합격, 추천 금지 |
| 손익비 | ≥ 1.5 | ❌ 불합격 |
| 낙폭(MDD) | ≥ -5% | ❌ 불합격 |
| 거래수 | ≥ 30건 | ⚠️ 신뢰도 부족 경고 |

---

## 현재 확정 파라미터 (CLAUDE.md 기준)

| 파라미터 | 값 | 비고 |
|---|---|---|
| STOP_LOSS | -0.025 | 28종 조합 중 EV 기준 최적 |
| TAKE_PROFIT | 0.07 | 실용 균형 |
| RSI_BUY_MIN/MAX | 25/70 | 백테스트 완화 결과 |
| VOLUME_SURGE_RATIO | 1.1 | 백테스트 완화 결과 |

**현재 운용 파라미터(TP=7%)의 백테스트 기준값** (2026-06-30, version=2026-W26-TP7, deployed=0):
손익비 3.09 / EV +0.3207 / MDD -1.09% / 거래 65건 — 실측 비교의 기준선.
다음 검토 조건: 실측 SELL 30건 완료 + 실측 손익비가 백테스트(**3.09**) 대비 30% 이내 괴리 시
TP=7% 유지·변경 재검토.

**TP=10%는 보류 이력**: 손익비 3.42, EV +0.2908, 거래 65건으로 합격이었으나
승률 29.2% 과소·강세장 과최적화 의심·실측 연속성 단절 우려로 2026-06-30 보류.

평가 시 현재 기준값은 CLAUDE.md "확정 파라미터" 표와 `db.get_last_model_version()`
(model_version 테이블, id DESC)을 참조할 것.
스킬 내 hardcoded 수치는 낡을 수 있으므로 반드시 DB 또는 CLAUDE.md를 확인한다.

## 실측 게이트 (model_trainer.py L.481-521과 연동)

- 실측 SELL < 30건: 백테스트 합격이어도 **PARAMS LOCKED** — 파라미터 변경 추천 금지
- 실측 게이트 확인 쿼리: `SELECT COUNT(*) FROM trades WHERE action='SELL'`
  - 근거: database.py L.23 (`action` 컬럼, `side` 없음)

## 실전 전환 판정 시 (예: "실전 가도 돼?")

전략 합격 여부만으로 답하지 말 것. **실전 전환은 `실전전환_체크리스트.md`의
선행 게이트(① 실측 SELL ≥ 30건 + 이 스킬의 합격 판정 + 실측-백테스트 괴리 30% 이내)와
절차(앱키 교체, 설정 원복 등)를 모두 통과해야 한다** — 판정 출력에 이 문서를 링크하고,
게이트 현황(SELL 누적 건수 등)을 함께 보고한다.

## Trading Council 5인 패널 출력 형식

요청을 받으면 반드시 이 형식으로 출력한다:

```
[퀀트 전략가] 기댓값·손익비 수치 판단 — 합격 기준 대비 수치 명시
[리스크 회의론자] 손실 시나리오, 과최적화 가능성, 데이터 함정 지적
[시장 크리에이티브] 맹점과 대안 전략 제시
[개발 운영자] 코드 구현 가능성, 다음 실행 단계
[자본 보호자] 실제 투자금 기준 최악 손실 금액 (3,000만원 × MDD 기준)

⚡ 불일치 요약: 패널 간 의견 충돌 핵심
✅/❌ 최종 판정 + 다음 실행 단계: 1. 2. 3.
```

---

## 반드시 지킬 규칙

- 기댓값 계산식을 반드시 보여준 뒤 판정
- 백테스트 추정치 / 실측치 혼용 절대 금지 — 반드시 구분 표기
- 실측 30건 미만이면 "신뢰도 부족 ⚠️" 경고 추가
- 수익률 숫자만 보고 "개선됨" 단정 금지
- 최종 판정은 ✅ 합격 / ❌ 불합격 으로 명시
